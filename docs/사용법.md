## 0. 무엇이 올라가나

한 번 돌리면 **글 하나에 답글 두 개**가 딸린 묶음이 올라간다.

```
본문        사진·영상과 함께 내 말투로 쓴 4~5줄
 └ 답글 1   [광고]
            🍲 요리 이름
            🛒 준비물 — 재료마다 분량까지
            👇 핵심재료를 권하는 한 줄
            상품 이름
            https://link.coupang.com/…
            https://link.coupang.com/…
   └ 답글 2  👩🏻‍🍳 만드는 법 1️⃣2️⃣3️⃣
            쿠팡파트너스 활동의 일환으로 일정액의 수수료를 제공받습니다
```

**쿠팡 링크가 안 붙으면 `[광고]` 와 대가성 문구도 안 붙는다.** 광고가 아닌 글에 광고 표기를 하지 않는다.

## 1. 시작하기 전에 딱 두 가지

**터미널**을 쓴다. 맥에서 `Cmd + 스페이스` → `터미널` 이라고 치면 열린다.

**모든 명령은 이 폴더에서** 친다. 터미널을 새로 열 때마다 한 번씩 쳐 준다.

```
cd ~/projects/coupas-auto
```

> `--env-file=.env.local` 은 열쇠 꾸러미를 읽어오는 부분이다. **빼면 안 된다.**

## 1-1. 터미널이 싫다면 — 설정 화면

### 늘 켜 두고 북마크해서 쓰기 (권장)

```
단추/설정화면 항상 켜두기.command
```

한 번만 더블클릭하면 됩니다. **맥이 켜지면 저절로 뜨고, 어쩌다 꺼져도 다시 뜹니다.**
찍히는 주소를 **북마크**해 두세요. **이 주소는 바뀌지 않습니다.**

> **처음 한 번**은 화면을 준비하느라 **1~2분** 걸릴 수 있습니다. 그동안은 그냥 기다리면 됩니다.

```
http://100.64.0.1:7788/?k=837eaf1d…      ← 아이폰에서도 같은 주소
http://127.0.0.1:7788/?k=837eaf1d…           ← 이 맥에서
```

둘 다 열려 있어서 테일스케일이 꺼져도 맥에서는 항상 들어갑니다.

끄려면 터미널에 `launchctl unload ~/Library/LaunchAgents/com.threads.dashboard.plist` 를 칩니다.

### 필요할 때만 켜기

```
단추/설정화면 켜기.command
```

터미널 창이 하나 열리고 **브라우저가 저절로 열립니다.** 끄려면 그 터미널 창에서 **Control + C**.

> 처음 더블클릭할 때 "확인되지 않은 개발자" 라고 막히면,
> 그 파일을 **오른쪽 클릭 → 열기 → 열기** 를 한 번만 해 주면 그다음부터는 그냥 열립니다.

터미널을 직접 쓰고 싶으면 `node 대시보드서버.mjs` 라고 쳐도 같습니다.

### 아이폰·아이패드에서 쓰고 싶다면

```
단추/설정화면 켜기 (아이폰에서도).command
```

이걸 더블클릭하면 **테일스케일 주소**로 켜집니다. 찍히는 주소를 아이폰 브라우저에
붙여넣으면 폰에서도 설정하고 돌려 볼 수 있습니다. 그 기기에도 테일스케일이 켜져 있어야 합니다.

> 테일스케일은 **내 기기끼리만 통하는 사설망**입니다. 인터넷에 열리는 게 아닙니다.

화면은 **세 칸**입니다. 넓은 화면에서는 나란히 놓이고, 노트북이나 폰에서는 위아래로 접힙니다.

| 어디 | 무엇 |
|---|---|
| **왼쪽** — 계정 | 지금 보고 있는 계정(@아이디 · 별칭 · **프로필 사진** · 분야 · 언어 · 제휴) 과 **다음 발행 시각** |
| | 맨 위에 자동 발행이 **초록 `ON` · 빨강 `OFF`** 로 보입니다 |
| **왼쪽** — 활동 | 팔로워 찾기 · 언어 길들이기 · **하트·댓글 활동** |
| **왼쪽** — 빠른 실행 | 보기만 / 글만 만들기 / **실제로 올리기** · 멈추기 |
| **가운데** — 수익 | 오늘·이번 달 수수료, 클릭, 주문, 최근 14일 막대 |
| **가운데** — 발행 현황 | 최근 7일 × 예정 시각 격자, **시·분을 골라** 자동 발행 켜고 끄기 |
| | 계정마다 **다른 분**에 돕니다 — 같은 시각이어도 동시에 안 올라갑니다 |
| **가운데** — 최근 올린 글 | 사진 · 본문 · 쿠팡 상품 · 링크 (20개) |
| **가운데** — 돌려 본 기록 | 빠른 실행을 누르면 여기에 한 줄씩 찍힙니다 |
| ▸ **오른쪽** — 열쇠 (맨 아래) | 뭐가 채워졌는지 ✓ ✗ 로 보고, 새 값을 넣어 저장 |
| | **열쇠 이름에 마우스를 올리면** 어디서 어떻게 받는지 세 줄이 뜹니다 (폰에서는 눌러서) |
| ▸ **오른쪽** — 말투 | 나를 한 줄로 · 말투 · 자주 쓰는 표현 · **글 예시 3편** |
| ▸ **오른쪽** — 피드 학습 검색어 | 홈에 원하는 글이 안 뜰 때 피드를 가르치는 낱말들 |

`▸` 가 붙은 칸은 접혀 있습니다. **제목을 누르면 펼쳐집니다.**
왼쪽 칸은 화면을 내려도 따라옵니다 — 어느 계정을 보고 있는지 놓치지 않게 하려는 것입니다.

오른쪽 위에서 **계정을 고르면 화면 전체가 그 계정 것으로 바뀝니다.**

### 계정 추가하기

**「＋ 계정 추가」를 누르면 설정 마법사가 뜹니다.** 한 화면에 하나씩만 물어보고,
여덟 걸음이면 그 계정이 돌 준비가 끝납니다.

| 걸음 | 무엇을 물어보나 |
|---|---|
| 1 | 스레드 계정 이름 · 별칭 · 분야 · 언어 · 제휴 마케팅 |
| 2 | 나를 한 줄로 |
| 3 | 어떻게 말하나 |
| 4 | 자주 쓰는 표현 |
| 5 | 글 예시 (셋까지) |
| 6 | 열쇠 — 토큰과 쿠키 |
| 7 | 언제 올릴까 — **시와 분을 골라서** (9-1절과 같은 고르개입니다) |
| 8 | 끝 |

**계정은 1걸음에서 이미 만들어집니다.** 그러니 중간에 「나중에 하기」로 닫아도 괜찮습니다.
남은 것은 대시보드에서 그 계정을 고르고 아래 칸에서 마저 채우면 됩니다.

**5·6·7걸음은 「건너뛰기」로 넘어갈 수 있습니다.** 다만 넘어가면 무엇을 못 하게 되는지
다음 화면에 빨간 글씨로 알려 줍니다.
- 예시를 건너뛰면 → 글이 밋밋해질 수 있습니다
- 열쇠를 건너뛰면 → 그 계정은 **아직 글을 못 올립니다**
- 시각표를 건너뛰면 → **자동으로 안 올라갑니다**

**분야에 맞는 예시가 뜹니다.** 뷰티 계정을 만들면 뷰티 예시가, 요리면 요리 예시가 나옵니다.

**6걸음의 토큰은 터미널에서 받습니다.** 화면에 적힌 명령을 그대로 복사해 터미널에 붙여넣고,
안내대로 진행한 뒤 받은 토큰을 마법사 칸에 붙여넣으면 됩니다.
넣은 값은 파일에만 저장되고 화면으로 다시 나오지 않습니다.

### 계정 고치기

계정 이름 옆 **「수정」** 을 누르면 이 넷을 고칠 수 있습니다.

| 무엇 | |
|---|---|
| 별칭 | 화면에 보일 이름 |
| 계정 분야 | 요리 · 뷰티 … |
| 사용 언어 | |
| 제휴 마케팅 | |

계정 이름 칸에는 **실제 스레드 아이디**가 보입니다 (`@example.cook`).
계정 고르는 칸에도 아이디가 별칭 왼쪽에 함께 보입니다.

**계정 이름은 못 바꿉니다.** 그 이름이 열쇠 파일 · 말투 파일 · 사진 폴더 · 기록 ·
발행 시각표, 그리고 **쿠팡 꼬리표**의 이름이기도 하기 때문입니다.
바꾸면 지금까지 쌓인 수익 통계가 끊깁니다. 이름을 바꾸려면 계정을 새로 만들어야 합니다.

**분야를 바꾸면 말투도 새 분야에 맞게 다시 잡습니다.** 고치기를 누르면
말투 설정이 다섯 걸음으로 이어집니다. 적어 두신 정체성 · 말투 · 자주 쓰는 표현 ·
내 글 예시는 그대로 남고, 분야가 정하는 뼈대(도입 방식 · 글 구조 · 형식)만 바뀝니다.

**말투 · 열쇠 · 발행 시각은 여기 없습니다.** 대시보드 아래 각 칸에서 고치면 됩니다.

### 발행 현황 동그라미 읽는 법

| | 뜻 |
|---|---|
| **● 초록** | 그 시각에 글이 올라갔습니다 |
| **◌ 회색** | 돌기는 했는데 못 올렸습니다. 쓸 만한 글이 없었거나 검색이 조였습니다 |
| **○ 빈** | 아직 그 시각이 안 됐거나, 기록이 없습니다 (맥이 꺼져 있었을 수 있습니다) |

동그라미에 마우스를 올리면 몇 시 몇 분에 돌았는지 나옵니다.

### 급히 멈추기

화면 맨 위에 띠가 하나 있습니다. 초록이면 **「재생 — 돌고 있습니다」** 이고
옆에 빨간 **「전부 멈추기」** 단추가 있습니다. 누르면 한 번 더 물어봅니다.
"예" 를 누르면 그 순간부터 **모든 계정**의 자동 발행이 멈춥니다.

멈춘 동안 발행 시각표는 지우지 않고 그대로 둡니다. 시각이 되면 프로그램은 평소처럼
깨어나지만 글을 안 올리고 기록에 "⏸ 멈춰 있습니다" 만 남깁니다.

다시 돌리려면 같은 자리의 빨간 **「다시 켜기」** 단추를 누릅니다.

> ⚠️ **「다시 켜기」는 전체 멈춤과, 지금 화면에 보이는 계정 하나만 풉니다.**
> 다른 계정이 따로 멈춰 있었다면 그 계정은 그대로 멈춰 있습니다. 그 계정을
> 풀려면 화면 위에서 그 계정을 골라 「다시 켜기」를 한 번 더 눌러야 합니다.

### 왜 안 올라갔나

**「왜 안 올라갔나」**를 누르면 여덟 가지 점검 항목이 펼쳐집니다. 항목마다
**됨** · **손봐야 함** · **확인 못 함** 중 하나가 붙고, 지금 상태가 한 줄로 나옵니다.

**손봐야 함** 항목에는 그 아래 **→** 로 시작하는 줄이 하나 더 있습니다. 그것이
오늘 해야 할 일입니다. 예를 들어 "마지막 발행 — 손봐야 함 — 31시간 전 →
시각표가 안 돌고 있을 수 있습니다" 라면, 시각표가 켜져 있는지부터 확인하면 됩니다.

이 칸은 **보기만 하는 칸**입니다. 눌러도 아무 것도 바뀌지 않습니다.

### 막힌 글

**「막힌 글」**을 누르면 발행 직전에 막힌 글의 목록이 나옵니다. 원글에는 없던
분량(예 — 원글엔 없던 "설탕 2T" 가 다시 쓴 글에 새로 생긴 경우)이 생기면, 그 글은
스레드에 올라가지 않고 여기에 담깁니다. 항목마다 무엇이 문제였는지, 본문 일부,
그리고 **「버리기」** 단추가 있습니다. 버리면 목록에서 사라지고 다시 뜨지 않습니다.

막힌 글은 이제 **어느 계정 것인지 함께 적힙니다.** 그래서 계정 화면마다 그 계정 글만 보입니다.
계정 표시가 없던 **옛 막힌 글 3편은 이제 어느 계정 화면에도 안 보입니다** — 지워진 것은 아니고
`계정/<계정이름>/media/막힌것/` 폴더에 그대로 있습니다.

**이 목록에 글이 자꾸 쌓이면** 관문 규칙이 너무 엄격하다는 뜻일 수 있습니다.
그런 일이 반복되면 다음에 저(또는 개발 세션)에게 알려 주세요 — 규칙을 손볼 때가 된 것입니다.

### 도달 — 내 글이 평소만큼 닿고 있나

**점검** 화면의 **도달** 칸입니다. 도달은 "이 계정 글이 평소 얼마나 조회되는가" 입니다.
스레드가 계정을 제재할 때는 막는 것부터 하지 않고 **말없이 도달을 줄이는 것부터** 합니다.
그래서 이 숫자가 조용히 떨어지는 것을 지켜봅니다.

**매일 아침 8시 10분에 저절로 잽니다** (2026-08-29 부터). 사람이 누를 것은 없습니다.
잰 결과는 파일에 쌓여서, 칸 아래 막대 그림으로 **최근 14일 추이**가 보입니다.
막대가 초록이면 평소만큼, 회색이면 조금 아래, 빨강이면 많이 떨어진 것입니다.

- **큰 숫자(%)** — 평소 대비 지금입니다. 100% 면 평소와 같습니다.
- **기준선** — "평소는 이만큼" 이라는 잣대입니다. 이 계정을 처음 재는 날 한 번 찍히고,
  그다음부터는 **저절로 안 바뀝니다.** 기준선이 매일 따라 내려가면 서서히 깎이는 것을 영영 못 잡습니다.
- **「기준값 다시 측정」 단추** — 잣대 자체를 지금 값으로 새로 찍습니다. 계정 성격을 크게
  바꿨을 때만 누르세요. 누르면 "전에 찍은 기준값을 덮어씁니다" 라고 한 번 더 물어봅니다.

**"도달 기준값을 아직 측정 안 했습니다"** 라고 뜨면 그 계정 글이 아직 5편이 안 된 것입니다.
3편으로 낸 평균은 숫자가 아니라서 일부러 안 냅니다. 글이 더 쌓이면 다음 날 아침에 저절로 뜹니다.

**떨어져도 텔레그램으로 알리지는 않습니다.** 아직 이 숫자가 얼마나 믿을 만한지 몇 주 지켜보는
중이라서, 헛알람을 보내느니 화면에만 쌓아 둡니다. 가끔 이 칸을 눈으로 봐 주세요.

### 자동 발행 켜고 끄기

**발행 현황 칸 맨 아래**에 시각을 넣는 칸과 단추가 있습니다.

```
올릴 시각 (쉼표로 나눠서. 24는 밤 12시입니다)
[ 8, 12, 16, 20, 24 ]   [자동 발행 켜기]  [끄기]
```

**「자동 발행 켜기」를 누르면** 그 시각마다 이 계정에 한 편씩 저절로 올라갑니다.
누르기 전에 한 번 더 물어봅니다. 끄면 즉시 멈춥니다.

> **간격이 4시간보다 좁으면 빨간 글씨로 알려 줍니다.** 막지는 않지만,
> 너무 붙여 올리면 글끼리 도달을 갉아먹습니다.

**계정이 여럿이면 시각을 엇갈리세요.** 같은 시각에 두 계정이 올리면 한 사람이 굴리는 게 보입니다.

```
첫 계정   08 · 12 · 16 · 20 · 24시
둘째 계정 10 · 14 · 18 · 22 · 02시
```

> **수익은 쿠팡 계정 전체 실적입니다.** 스레드 계정별로는 아직 안 갈립니다 —
> 쿠팡이 우리가 붙인 꼬리표(SubID)를 빈 값으로 돌려주기 때문입니다.
> 나중에 채워 주면 그때부터 갈립니다.

> 🔒 **이 화면은 내 컴퓨터에서만 열립니다.** 같은 와이파이에 있는 다른 사람도 못 들어옵니다.
> 주소에 붙은 열쇠말은 켤 때마다 새로 만들어지고, **채워진 열쇠 값은 화면에 다시 보여 주지
> 않습니다.** 바꿀 때만 새로 넣으면 됩니다.

끄려면 그 터미널 창에서 **Control + C** 를 누릅니다.

## 페이스북 앱 만들기와 스레드 연결

스레드에 글을 자동으로 올리려면 **페이스북(메타) 개발자 앱**이 하나 있어야 합니다.
앱 = 스레드가 "이 프로그램은 내가 허락한 프로그램이다" 라고 알아보게 해 주는 출입증입니다.
한 번만 만들어 두면 됩니다.

1. 브라우저로 **developers.facebook.com** 에 들어가 페이스북 계정으로 로그인합니다.
2. 위쪽 **「내 앱」** 을 누르고 **「앱 만들기」** 를 누릅니다.
3. **사용 사례**를 고르는 화면이 나오면 **「Threads API」** 를 고릅니다.
   앱 이름은 아무거나 적어도 됩니다. 우리끼리만 쓰는 이름입니다.
4. 앱이 만들어지면 앱 설정 화면으로 들어갑니다. 여기서 두 가지를 확인합니다.
   - **앱 ID** — 화면에 바로 보입니다. 앱의 이름표입니다.
   - **앱 시크릿** — **「보기」** 를 눌러야 보입니다. 앱의 비밀번호입니다.
     **아무에게도 보여 주지 않습니다.** 캡처해서 대화창이나 메신저에 붙여넣지 않습니다.
5. 왼쪽 메뉴에서 **Threads API 사용 사례 설정**으로 들어가, **「재전송 URI(Redirect Callback URL)」** 칸에
   아래 주소를 그대로 적습니다.
   ```
   https://localhost/
   ```
   이 주소는 실제로 열리지 않습니다. 스레드가 로그인을 끝낸 뒤 **주소창에 결과를 실어 돌려주는**
   자리일 뿐입니다. 그래서 페이지가 안 열려도 정상입니다 — [11절](#11-알아두면-좋은-것) 의
   토큰 받기 순서에서 그 주소창 전체를 복사해 씁니다.

### 이 스레드 계정을 쓸 수 있게 테스터로 등록하기

앱만 만들어서는 아직 아무 스레드 계정도 못 씁니다. **개발 모드인 동안은 테스터로 등록한
계정만** 앱에 로그인할 수 있습니다.

1. 개발자 앱 화면에서 **「앱 역할」 → 「역할」 → 「사람 추가」** 를 누릅니다.
2. 글을 올릴 그 스레드 계정을 **「Threads 테스터」** 로 추가합니다.
3. 이제 **스레드 앱(폰)** 을 엽니다. 그 계정으로 로그인한 상태에서
   **설정 → 계정 → 웹사이트 권한 → 초대** 로 들어가면 방금 보낸 초대가 와 있습니다.
   **수락**을 눌러야 앱이 그 계정을 실제로 쓸 수 있습니다.

계정을 여러 개 굴려도 앱은 이거 하나면 됩니다. **앱 ID·앱 시크릿은 계정 수와 상관없이
하나만 있으면 되고**, `.env.local` 에 한 번 넣어 모든 계정이 같이 씁니다. 계정을 새로 붙일 때마다
할 일은 위 테스터 추가·초대 수락 두 단계뿐입니다 ([10-2절](#10-2-계정-두-개-이상-굴리기) 참고).

### 60일마다 다시 받아야 하는 것

스레드가 주는 로그인 토큰(발행 열쇠)은 **60일**이 지나면 끊깁니다. 앱 ID·앱 시크릿은
그대로 두고, 토큰만 다시 받으면 됩니다. 설정 화면 열쇠 칸의 **「자동발급」** 단추를 누르거나
터미널에서 `threads-login.mjs` 를 다시 돌립니다. 자세한 순서는 [11절](#11-알아두면-좋은-것) 을 봅니다.

### 막히면

- 스레드 로그인 뒤 허용 화면에 이 계정이 안 보인다 → 초대 수락을 안 한 것입니다. 폰에서 다시 확인합니다.
- **「앱이 개발 모드입니다」** 같은 경고가 뜬다 → 정상입니다. 우리끼리만 쓰는 앱이라 일부러 그렇게 둡니다.
- 재전송 주소(`https://localhost/`)로 넘어간 뒤 페이지가 안 열린다 → 정상입니다.
  그 페이지를 여는 게 아니라 **주소창에 찍힌 글자를 읽어 오는 것**이 목적입니다.

## 3. 글을 만들어만 보기 — 아직 안 올린다

```
node --env-file=.env.local run.mjs 레시피 요리 한식 --받기 --재구성
```

- `--받기` — 사진·영상을 `계정/<계정이름>/media/받은것/` 에 내려받는다
- `--재구성` — 내 말투로 다시 쓴다. **파일로만 저장한다**

만들어진 글이 화면에 그대로 찍힌다. 마음에 안 들면 [8절](#8-말투-바꾸기)에서 말투를 고치고 다시 돌린다.

## 4. 전부 자동 — 실제로 계정에 올라간다

```
node --env-file=.env.local run.mjs 레시피 요리 한식 --받기 --재구성 --발행
```

**`--발행` 이 있어야만 계정에 올라간다.** 이게 없으면 절대 안 올라간다.

아무 옵션도 안 주면 **5편을 살펴보고 그중 1편만** 올린다.
처음엔 이대로 한 번 돌려서 눈으로 확인해 보는 게 좋다.

## 5. 조절할 수 있는 것

| 무엇 | 어떻게 | 설명 |
|---|---|---|
| 검색어 | 뒤에 그냥 나열 | `run.mjs 레시피 요리 집밥 한식` |
| 살펴볼 개수 | `TOP=8` | 몇 편을 **들여다볼지**. 안 적으면 5 |
| 올릴 개수 | `LIMIT=2` | 몇 편을 **올릴지**. 안 적으면 1 |
| 내려받기 | `--받기` | 빼면 사진·영상을 안 받는다 |
| 글 다시 쓰기 | `--재구성` | 빼면 수집만 한다 |
| 실제 발행 | `--발행` | **이게 있어야만 계정에 올라간다** |
| 링크 끄기 | `NOLINK=1` | 쿠팡 링크 없이 올린다. `[광고]` 와 대가성 문구도 안 붙는다 |
| 계정 고르기 | `PROFILE=b` | 둘째 계정으로 올린다 → [10-2절](#10-2-계정-두-개-이상-굴리기) |

> **`TOP` 과 `LIMIT` 은 다르다.** `TOP` 은 후보를 몇 편 볼지, `LIMIT` 은 실제로 몇 편 올릴지다.
> 레시피가 안 실린 글은 걸러지므로 `TOP` 을 넉넉히 잡되, `LIMIT` 으로 올릴 편 수를 묶어 둔다.

**검색어는 여러 개 넣는 게 좋다.** `집밥` 만 치면 밥상 사진 위주라 레시피가 거의 없다.
`레시피` · `요리` · `한식` 을 섞으면 잘 걸린다.

## 6. 등급이 뭔가

**좋아요 ÷ 조회수** 로 매긴다. 좋아요 숫자만 큰 글이 아니라
**적게 보여주고도 반응이 좋았던 글**을 찾는 것이다.

| 등급 | 기준 |
|---|---|
| 플래티넘 | 2.0% 이상 |
| 골드 | 1.2% 이상 |
| 실버 | 0.6% 이상 |
| 브론즈 | 그 아래 |
| 미달 | **조회 5,000을 못 넘긴 글** |

고르는 순서는 **등급 높은 것부터**다.

```
플래티넘 → 골드 → 실버 → 브론즈 → 미달
```

플래티넘이 없으면 골드를, 골드도 없으면 실버를 쓴다.

> **조회 5,000 문턱이 왜 있나.** 문턱이 없으면 기준이 거꾸로 돈다. 조회 1회에 좋아요 1개인 글이
> 100% 로 1등을 해 버린다. 표본 76개로 확인한 사실이라 문턱을 뒀다.
> 그래서 **비율이 90% 여도 조회가 적으면 맨 뒤로 간다.**

등급 칸에 `알수없음` 이 뜨면 [10절](#10-조회수등급-켜기-한-번만-하면-된다)을 보면 된다.

## 7. 올라가는 글의 생김새 — 절대 안 바뀌는 규칙

이건 **프로그램이 강제**한다. LLM 이 마음대로 바꿀 수 없다.
주소를 지어내거나 문구를 빠뜨리면 수수료가 날아가고 법적 문제가 생기기 때문이다.

| 규칙 | 내용 |
|---|---|
| **`[광고]`** | 첫 답글 맨 앞 |
| **한 줄 소개** | 링크 바로 위. 왜 이 재료인지 한 마디 |
| **링크 자리** | **준비물 문단 끝.** 재료를 읽는 그 자리에서 바로 사러 갈 수 있게 |
| **링크 두 줄** | 상품 이름은 한 번, **주소만 두 줄** |
| **대가성 문구** | 레시피 맨 아래 |
| **핵심재료** | 요리를 그 요리로 만드는 재료 하나. 식빵 프렌치토스트면 **식빵**이지 계란·우유가 아니다 |
| **비밀재료** | 원글이 `킥소스` 처럼 별명으로 부르면 정체를 알아내 링크한다. **모르면 그 글은 안 쓴다** |
| **단위 표기** | 큰술은 `2T (큰술)`, 작은술은 `1t (작은술)` 로 함께 적는다 |
| **로켓만** | 로켓 배송 배지가 없는 상품은 안 쓴다 |
| **490자** | 스레드 한도는 500자다. 넘으면 답글로 나눠 잇는다 |
| **미리보기 막기** | 링크가 든 답글에 사진을 함께 올려 카드가 안 뜨게 한다 |

**`[광고]` 와 대가성 문구를 지우지 않는다.** 표시광고법상 필요한 표기다.

## 8. 말투 바꾸기

가장 쉬운 방법은 설정 도우미를 다시 돌리는 것이다. 네 가지만 물어본다.

```
node 설정.mjs
```

직접 고치고 싶으면 이렇게 연다.

```
open -e ~/projects/coupas-auto/계정/example.cook/persona.json
```

텍스트편집기가 열린다. 고치고 `Cmd + S` 로 저장하면 **다음 실행부터** 반영된다.

| 항목 | 무엇을 정하나 |
|---|---|
| `정체성` | 내가 어떤 사람인지 |
| `말투` | 어떻게 말하는지 |
| `자주 쓰는 표현` | ㅋㅋ · ㅠㅠ 같은 것 |
| `글 구조` | **본문**을 어떤 순서로 풀어가는지 |
| `본문 길이` · `본문 이모지` | 본문 4~5줄, 이모지는 끝에 하나 |
| **`레시피 형식`** | 🛒 준비물 · 👩🏻‍🍳 만드는 법 · 1️⃣2️⃣3️⃣ — **레시피 모양이 여기서 나온다** |
| `레시피 길이` · `레시피 규칙` | 25줄 이내, 원문 분량은 그대로 |
| `지켜야 할 것` · `쓰지 말 것` | 피하고 싶은 표현 |
| **`내 글 예시`** | **실제로 쓴 글. 이게 제일 강력하다** |

> 설명을 열 줄 쓰는 것보다 **실제 내 글 한 편을 붙여넣는 게** 훨씬 정확하다.
> 반응이 좋았던 글일수록 좋다. 두세 편이면 충분하다.

## 8-1. 말투가 막막하면 — 추천받기

말투 칸(그리고 계정 만들기 마법사의 말투 단계)에 **「✨ 추천받기」** 단추가 있습니다.

누르면 이런 일을 합니다.

1. 그 계정 **분야에서 지금 잘 퍼지는 계정**들을 스레드에서 찾습니다
2. 팔로워 대비 조회수(**확산**)가 높은 계정을 고릅니다
3. 그 계정들의 본문과 글타래를 읽어 **결**을 뽑습니다
4. **나를 한 줄로 · 말투 · 자주 쓰는 표현** 세 칸을 채워 줍니다

**1분쯤 걸립니다.** 그동안 단추가 잠기고 무엇을 하는 중인지 보여 줍니다.

마음에 안 들면 옆의 **「다시 추천」**을 누르세요. **다른 검색어로 다시 찾습니다.**

### 도는 동안 무엇이 보이나

**동그라미가 돌고, 지금 무엇을 하는 중인지 한 줄로 보입니다.** 몇 초 됐는지도 함께 나옵니다.

```
⟳ 팔로워 찾기 · 15초   [중단]
"時短レシピ" 로 걷는 중... (4/4)
```

**「중단」**을 누르면 멈춥니다. 2초쯤 걸립니다 — 지금 받고 있던 것 하나는 마치고 멈춥니다.
중단해도 아무것도 저장되지 않으니 다시 누르시면 됩니다.

**돌리는 중에 새로고침을 하셔도 괜찮습니다.** 화면이 다시 열리면서 **돌던 일을 알아서 다시 붙잡습니다** —
진행이 그대로 보이고, 중단도 되고, 끝나면 결과도 칸에 채워집니다.
그 일이 다른 계정 것이었으면 **그 계정으로 화면을 옮겨** 줍니다.

「언어 길들이기」·「하트·댓글 활동」은 **가운데 「돌려 본 기록」**에 한 줄씩 찍히고,
**「빠른 실행」의 「멈추기」**로 멈춥니다.

### 알아두실 것

- **채우기만 하고 저장하지 않습니다.** 고쳐 쓰신 뒤 「말투 저장」을 눌러야 반영됩니다
- **외국어 계정은 네 칸이 다 그 언어로 채워집니다.** 일본어 계정이면 정체성·말투·표현이 일본어입니다.
  **칸 밑에 한국어 뜻**을 적어 드리니 무슨 말인지 보고 고치시면 됩니다.
  왜 그 언어여야 하냐면 — **자주 쓰는 표현은 글에 그대로 박히는 낱말**이라, 한국어로 두면
  일본어 글에 「ㅋㅋ」·「대박」이 섞입니다
- **글 예시도 채워 드립니다.** 그 분야에서 **실제로 잘 퍼진 글**을 찾아 그대로 넣습니다.
  칸 옆에 `@작성자 · 조회수 · 확산` 이 적힙니다 — 남의 글이라는 뜻입니다.
  **이미 적어 두신 글은 덮지 않습니다.** 내가 올린 글로 바꿔 넣으시면 그게 더 정확합니다
- **어느 계정을 보고 뽑았는지 함께 보여 드립니다.** 눌러서 직접 확인해 보세요
- 남의 문장을 베끼지 않습니다. 여러 계정에 공통으로 보이는 **방식**만 뽑습니다
- 계정을 열 개까지 찾지만 **더 적게 찾을 때도 있습니다.** 그때는 몇 개를 찾았는지 알려 드립니다

## 9. 양식은 어디서 정해지나

세 군데로 나뉘어 있다.
**문서(`HANDOFF.md` 같은 것)는 사람이 읽는 설명서일 뿐, 프로그램은 읽지 않는다.**

```
계정/<이름>/persona.json ─┐
                          ├─→ 지시문 만들기 ─→ LLM ─→ 본문 · 레시피 · 핵심재료 · 한줄소개
compose.mjs 뼈대          ┘                            │
                                             ├─→ [광고] · 링크 · 대가성 문구 심기
                                             ├─→ 490자 답글 조각내기
                                             └─→ 본문 + 답글 발행
```

| 무엇 | 어디서 | 내가 고쳐도 되나 |
|---|---|---|
| 말투 · 본문 흐름 · 레시피 생김새 | **`계정/<계정이름>/persona.json`** | **된다. 여기만 고치면 된다** |
| 분량 지키기 · 지어내지 않기 같은 뼈대 | `src/compose.mjs` | 코드다. 안 건드리는 게 좋다 |
| `[광고]` · 링크 자리 · 대가성 문구 | `src/compose.mjs` | 코드가 강제한다 |
| 답글 나누기 · 발행 | `src/publish.mjs` | 코드가 강제한다 |

**LLM 이 만드는 것은 본문과 레시피 본체뿐**이고, 나머지 껍데기는 전부 프로그램이 붙인다.

## 9-1. 발행 시각 고르기

「발행 현황」 칸에서 **시와 분을 골라** 정합니다. 한 줄이 «몇 시 몇 분» 하나입니다.

```
[08시 ▾] [32분 ▾] ✕
[11시 ▾] [32분 ▾] ✕
＋ 시각 추가
[자동 발행 켜기]  [끄기]
```

- **＋ 시각 추가**를 누르면 마지막 시각에서 4시간 뒤가 기본으로 들어갑니다 (조사 권고가 최소 4시간입니다)
- **✕** 로 그 줄을 뺍니다
- **「자동 발행 켜기」**를 눌러야 실제로 등록됩니다. 고르기만 하면 아직 아무 일도 안 일어납니다
- 왼쪽 계정 카드 맨 위에 **초록 `ON` · 빨강 `OFF`** 로 지금 켜져 있는지 보입니다

**다른 계정과 같은 시·분을 고르면** 그 줄이 빨갛게 되고 «어느 계정과 겹치는지» 가 적힙니다.
켜기를 누르면 **팝업으로 한 번 더 묻습니다.** 그래도 진행하시면 그대로 등록됩니다 — 막지는 않습니다.

> 같은 순간에 두 계정이 올라가면 스레드가 수집을 조이고(같은 IP), 크롬이 한꺼번에 여러 개 뜹니다.
> 웬만하면 **15분 이상 벌려** 주세요.

### 계정끼리 몇 분 벌릴지 (2026-09-03)

카드 **맨 아래**에 이 칸이 있습니다.

```
계정별 발행시각 간격  [20분 ▾]  [저장]
```

- **1분부터 59분까지** 고를 수 있습니다. 「저장」을 누르면 «20분 간격으로 저장되었습니다.» 가
  뜨고 **3초 뒤에 사라집니다**
- 이 값은 **계정마다가 아니라 이 컴퓨터 전체의 규칙**입니다. 어느 계정 화면에서 바꾸든 같습니다
- **「자동 배정」**이 이 값을 씁니다. 고른 시(9시·12시 …) 안에서 이미 예약된 계정과
  이만큼 떨어진 **가장 빠른 분**에 넣고, 그 시가 꽉 찼으면 **다음 시로 밉니다**
- 바꿔도 **이미 켜 둔 시각표는 안 바뀝니다.** 「자동 배정」을 다시 누르고
  「이 시각으로 다시 켜기」를 눌러야 새 간격으로 잡힙니다

> 좁게 잡을수록 계정이 촘촘히 들어갑니다. 다만 몇 분 차이로 두 계정이 연달아 올라가면
> **같은 사람이 굴리는 것이 눈에 보입니다.** 그래서 처음 값은 20분입니다.

## 9-2. 외국어 계정 — 언어 피드 길들이기

**일본어·영어 계정은 홈이 그 언어 글로 차 있어야 돕니다.** 우리 수집기는 홈을 내려가며 글을 걷는데,
홈이 한국어 글로 차 있으면 **일본어 계정이 아무것도 못 걷습니다.**

피드를 정하는 것은 **앱 언어 설정이 아닙니다.** 바꿔도 피드는 안 바뀝니다.
정하는 것은 **누구를 팔로우했는지 · 무엇을 열어 봤는지 · 어디에 머물렀는지** 입니다.

### 대시보드에서 켜기

왼쪽 **「활동」** 칸에서 **「언어 길들이기」**를 누르면 **지금 한 판** 돕니다.
그 아래 **「켜기」**를 누르면 그 뒤로 저절로 돕니다.
그 뒤로는 **3시간마다** 저희가 그 계정으로 홈을 열어, 그 언어 글 3~6편을 4~9초씩 보고 나옵니다.
밤(0~7시)에는 안 돕니다. 들어가는 시각도 0~25분씩 흩뜨립니다 — 사람은 정각마다 딱딱 들어오지 않습니다.

**한국어 계정은 켜기 단추가 잠겨 있습니다.** 홈이 이미 한국어로 차니 할 일이 없습니다.

### 팔로우는 직접 하셔야 합니다 — 이게 제일 셉니다

길들이기만으로는 한계가 있습니다. **홈에 그 언어 글이 아예 없으면 열어 볼 것도 없습니다.**
처음에 그 언어 요리 계정 **30~50개를 손으로 팔로우**해 주시면 그 뒤부터 길들이기가 굴러갑니다.

**「팔로워 찾기」**를 누르면 그 언어에서 **잘 퍼지는 계정 목록**을 링크로 뽑아 드립니다.
1분쯤 걸립니다. 링크를 눌러 열고 팔로우만 하시면 됩니다.
**팔로우는 프로그램이 누르지 않습니다** — 대량 팔로우가 계정이 막히는 첫째 원인입니다.

## 9-3. 하트·댓글 활동 — 그 언어를 못 읽으실 때

일본어·영어 계정을 키우려면 남의 글에 반응해야 하는데, 그 언어를 못 읽으면 스스로 하기 어렵습니다.
그래서 **저희가 대신 합니다.** 왼쪽 「활동」 칸의 **「하트·댓글 활동」**을 누르시면 됩니다.

### 한 번 누르면 이만큼 합니다

| | |
|---|---|
| 하트 | **4~6개.** 그 언어 글에만 |
| 댓글 | **1개.** 그 언어로 씁니다 |
| 하루 한계 | 하트 40개 · 댓글 6개까지. 그 이상은 안 합니다 |
| 안 하는 것 | **팔로우.** 그리고 밤(0~7시)에는 아무것도 안 합니다 |

**같은 글에 두 번, 같은 사람에게 하루 두 번은 하지 않습니다.** 사람이 아닌 것이 바로 보이기 때문입니다.

### 무슨 말이 나갔는지 꼭 보여 드립니다

댓글은 **한국어 뜻을 함께** 기록에 찍습니다. 이렇게 나옵니다.

```
· @takema_38 의 글에 일본어로 댓글을 쓴다
·   올릴 댓글 — こういうの大好きです！おにぎりの具、何入れてますか？
·   한국어 뜻 — 이런 거 정말 좋아해요! 주먹밥 속은 무엇을 넣으셨어요?
```

**내 계정으로 나가는 말인데 못 읽으면 안 됩니다.** 그래서 한국어 뜻이 없으면 아예 안 올립니다.

### 댓글이 지키는 것

- **"만들어 봤어요" 라고 안 씁니다.** 실제로 따라 해 본 게 아니니 거짓말입니다
- 링크 · 해시태그 · 내 계정 홍보를 넣지 않습니다
- 칭찬만 하지 않고 **물어봅니다.** 답이 오면 대화가 됩니다
- 남의 외모 · 몸 · 정치 · 종교 이야기는 하지 않습니다

### 먼저 보고 싶으시면

**아무것도 안 누르고 무엇을 할지만 보는 방법**이 있습니다. 터미널에 이렇게 칩니다.

```bash
node --env-file=.env.local --env-file=.env.sample_gohan src/교류하기.mjs sample_gohan --보기만
```

### 알아두실 위험

**스레드는 자동화를 약관으로 금지합니다.** 하트·댓글이 실제로 나가는 행동이라 계정이 제한될
가능성이 있습니다. 그래서 **시각표에 걸지 않았습니다** — 사람이 단추를 누를 때만 돕니다.
하루 한두 번 정도로 쓰시는 것을 권합니다.

## 9-3-b. 두 활동 단추는 「초안」부터 만듭니다 — 확인하고 올리세요

**「지금 한 번 돌리기」·「내 글 댓글에 답하기」를 누르면 바로 올라가지 않습니다.** (2026-08-26 부터)
프로그램이 홈을 훑거나 내 글을 열어 **무엇을 할지 초안만** 만들고 멈춥니다. 아무것도 남에게 나가지 않습니다.

1. 단추를 누릅니다. 가운데 「돌려 본 기록」에 진행이 찍힙니다.
2. 끝나면 활동 칸 아래에 **초안**이 뜹니다 — 어느 글에 하트를 누를지, 어떤 댓글·답글을 쓸지, **한국어 뜻**까지.
3. 읽어 보고 괜찮으면 **「이대로 올리기」**. 한 번 더 묻고, **읽으신 그것**이 그대로 나갑니다 (다시 만들지 않습니다).
4. 마음에 안 들면 **「버리기」**. 다시 단추를 누르면 새 초안이 나옵니다.

**완전 자동 스위치** — 단추 줄 오른쪽에 있습니다. 표시가 「수동」이면 초안 방식입니다. 켜면 단추가 초안 없이 **바로** 올립니다 (켤 때 한 번, 누를 때 한 번 묻습니다).
사람이 매번 확인하기 번거로워졌을 때 켜세요. 계정마다 따로 기억합니다.

초안은 파일(`활동초안.<계정>.교류.json` · `활동초안.<계정>.답하기.json`)로 남아 새로고침해도 사라지지 않고,
올리면 지워집니다 — 같은 초안이 두 번 올라가지 않게.

## 9-4. 내 글 댓글에 답하기 — 내 글에 온 댓글을 그냥 두지 않기

9-3 이 **남의 글**에 반응하는 것이라면, 이것은 **내 글에 달린 남의 댓글**에 답하는 것입니다.
왼쪽 「활동」 칸의 **「내 글 댓글에 답하기」**를 누르시면 됩니다. 한 번 물어보고 시작합니다.

### 한 번 누르면 이만큼 합니다

1. 최근 내 글 **10편**을 스레드 화면에서 하나씩 엽니다 (API 가 아니라 사람처럼 화면에서 읽습니다).
2. 남이 단 댓글 가운데 **아직 답 안 한 것**을 고릅니다. 바로 아래에 제 답이 붙어 있으면 답한 것으로 봅니다.
3. 그 댓글에 **하트**를 누르고, 3~7초 읽은 뒤 답글을 만듭니다.
4. 답은 **내 글과 레시피에 있는 것을 먼저** 씁니다. 거기 없는 질문(도구·대체 재료·보관법 같은 것)은
   AI 가 **웹을 검색해서** 일반적인 요령으로 답합니다. 그래도 모르면 **「잘 모르겠다」**고 씁니다.
   칭찬·인사에는 한 문장으로 고마움만 답합니다.
5. 답글을 올리고, 화면에 보이는 것까지 확인합니다.
6. **한 번에 5개, 하루 10개**까지입니다.

### 무엇을 답했는지는 「기록」 쪽에서

**기록** 쪽 「활동 기록」에 이렇게 남습니다.

> 내 글 답글 — @누구 「냄비는 어떤건가요?」 → (그 언어 답글) (뜻: 한국어 뜻) · 내글

맨 뒤 「내글 · 검색 · 인사 · 모름」이 **답을 어디서 가져왔는지**입니다. 「검색」이 많으면 글에 적을 것이
빠졌다는 뜻이고, 「모름」이 보이면 그 댓글은 직접 봐 주세요.

### 미리 보고 싶으면

```bash
node --env-file=.env.local --env-file=.env.sample_gohan src/답하기.mjs sample_gohan --보기만
```

하트도 안 누르고 답글도 안 올리고, **「올릴 뻔한 답글」과 한국어 뜻만** 보여 줍니다.

### 알아두실 것

- 9-3 과 같은 위험이 있습니다. **시각표에 걸지 않았습니다.** 사람이 누를 때만 돕니다.
- **밤(23시~8시)에는 안 돕니다.** 새벽에 답글이 찍히면 사람이 아닌 것이 보입니다.
- 화면 순서로 「답했나」를 짐작하므로 드물게 틀릴 수 있습니다. 다만 한 번 답한 댓글은 장부에 남아 **두 번은 안 답니다.**

### 피드 학습 검색어 — 홈에 원하는 글이 안 뜰 때

글은 **홈 화면을 내려가며** 걷습니다. 그런데 홈에 원하는 글이 안 뜨면 걷을 것이 없습니다.
그때 이 낱말들로 **직접 찾아 들어가 글을 봅니다.** 그러면 스레드가
«이 사람은 이런 글을 본다» 고 배워서 **홈에 그런 글을 띄워 줍니다.**

오른쪽 **「피드 학습 검색어」** 칸에서 **키워드를 적고 엔터**를 누르면 주머니로 담깁니다.
**×** 를 누르면 빠집니다. 담거나 빼면 **바로 저장됩니다** — 따로 저장 단추가 없습니다.

**추천 키워드 셋이 아래에 떠 있습니다.** 그 계정의 **분야와 언어**에 맞는 것들입니다 —
한국어 계정에는 `한식`·`자취요리`, 일본어 계정에는 `作り置き`·`時短レシピ`,
영어 계정에는 `one pan dinner`·`quick lunch idea` 처럼 나옵니다.
**누르면 그대로 담기고**, 옆의 **↻** 를 누르면 다른 셋이 나옵니다.

「언어 길들이기」를 돌릴 때 **한 판에 두 낱말씩 돌려 가며** 씁니다.
**한 낱말을 하루에 여러 번 두드리면 스레드가 그 낱말 결과를 줄입니다.**
그래서 여러 개(대여섯 개 이상) 넣어 두시는 것이 좋습니다.

### 잘되고 있는지 보는 법

칸 안에 **그 언어 비율**이 찍힙니다. 처음 재 본 값입니다.

| 계정 | 걷은 글 | 그 언어 비율 |
|---|---|---|
| 스위트데이디너 (영어) | 23편 | **70%** — 이미 쓸 만합니다 |
| 즈보라밥 (일본어) | 43편 | **5%** → 팔로우 뒤 다시 재니 **48%** 로 올랐습니다 |

**이 숫자가 며칠에 걸쳐 오르면 듣는 것이고, 안 오르면 팔로우를 더 하셔야 합니다.**

## 10. 조회수·등급 켜기 (한 번만 하면 된다)

등급 칸에 `알수없음` 이 뜬다면 이걸 안 한 것이다.
스레드가 **로그인한 사람에게만 조회수를 보여주기** 때문이다. 한 번 넣으면 보통 몇 달 간다.

1. 크롬에서 **threads.com 에 로그인된 상태로** 아무 글이나 연다.
2. 화면 아무 데나 **오른쪽 클릭 → "검사"**. 오른쪽에 개발자 창이 열린다.
3. 그 창 위쪽 탭에서 **`Network`** 를 누른다.
4. 그 상태로 **⌘R** 로 새로고침한다. 목록이 좌르륵 채워진다.
5. 목록 **맨 위 항목**을 누른다.
6. 오른쪽 **`Headers`** 탭에서 아래로 내려 **`Request Headers`** 를 찾는다.
7. **`cookie:`** 로 시작하는 줄의 **뒷부분 전체**를 복사한다. 아주 길다. 중간에 잘리면 안 된다.
8. 터미널에 `open -e .env.local` 을 치면 편집기가 열린다. 맨 아래 한 줄 넣고 저장한다.

```
THREADS_COOKIE="여기에_붙여넣기"
```

> ⚠️ 이 값은 **내 스레드 로그인 그 자체**다. 가진 사람은 비밀번호 없이 내 계정에 들어온다.
> 대화창이나 메신저에 붙여넣지 말고 이 파일에만 넣는다.

확인은 `node --env-file=.env.local run.mjs 레시피` 로 한다.
**됐으면** 등급과 조회수가 찍히고, **안 됐으면** `⚠ 쿠키를 넣었는데 조회수가 안 온다` 라고 알려 준다.

## 10-1. 자동으로 올리게 두기

**하루 다섯 번 저절로 올라갑니다.** 맥을 켜 두기만 하면 됩니다. 이미 켜져 있습니다.

```
아침 8시 · 낮 12시 · 오후 4시 · 저녁 8시 · 밤 12시   →  하루 5편
```

**쿠팡 링크는 매번 붙습니다.** 따라서 `[광고]` 표기와 대가성 문구도 매번 들어갑니다.

| 하고 싶은 것 | 치는 것 |
|---|---|
| 잘 켜져 있나 | `launchctl list \| grep example` |
| 무슨 일이 있었나 | `tail -40 logs/example.cook-$(date +%Y-%m).log` |
| 지금 한 번 돌리기 | `launchctl start com.threads.auto.example.cook` |
| **멈추기** | `launchctl unload ~/Library/LaunchAgents/com.threads.auto.example.cook.plist` |
| 다시 켜기 | `launchctl load ~/Library/LaunchAgents/com.threads.auto.example.cook.plist` |

> 2026-08-28 전에는 이 계정이 이름 없이 `com.example.threads`·`logs/2026-08.log` 를 썼습니다. 지금은 다른 계정처럼 계정 이름(`example.cook`)이 파일 이름에 붙습니다.

기록은 이렇게 남습니다.

```
═══ 2026-08-19 15:00:04 ═══
  올림 → 10000000000000002  답글 2개
✅ 올렸다
```

매 판 끝에 넷 중 하나가 남습니다.

| 표시 | 뜻 |
|---|---|
| `✅ 올렸다` | 한 편 올라갔습니다 |
| `⏭ 올린 것 없음` | 쓸 만한 글이 없었습니다. **고장이 아닙니다** |
| `⏸ 건너뜀` | 직전에 올린 지 얼마 안 됐습니다. 아래 설명을 보세요 |
| `‼️ 실패` | 뭔가 잘못됐습니다. 그 위 줄에 이유가 있습니다 |

**`⏸ 건너뜀` 이 왜 있나.** 맥이 자는 동안 지나간 시각들을 깨어난 뒤 **한꺼번에** 실행합니다.
그대로 두면 글이 연달아 올라가서 스레드에서 제일 안 좋은 모양이 됩니다.
그래서 **마지막으로 올린 지 150분이 안 됐으면 그 판을 건너뜁니다.**

## 10-2. 계정 두 개 이상 굴리기

계정 이름을 정해서 파일을 하나씩 더 만들면 됩니다. 이름은 **영문·숫자로 8자까지**입니다.
**이제 모든 계정이 똑같이 생겼습니다** — 첫 계정이든 나중에 만든 계정이든 파일 이름 짓는 방식이 같습니다.

| 무엇 | 계정 이름을 `b` 라 하면 |
|---|---|
| 열쇠 | `.env.b` |
| 말투 | `계정/b/persona.json` |
| 기록 | `logs/b-2026-08.log` |
| 쿠팡 꼬리표 | `b...` — **어느 계정이 벌었는지 갈립니다** |

```bash
./자동발행.sh example.cook   # 첫 계정
./자동발행.sh b              # 둘째 계정
```

### 둘째 계정 켜는 순서

1. **메타 개발자 앱에 그 계정을 추가**합니다 (앱 역할에 테스터로 넣어야 할 수 있습니다)
2. 그 계정으로 스레드에 로그인한 채 토큰을 받습니다
   ```bash
   node --env-file=.env.local threads-login.mjs b
   ```
3. 그 계정의 **쿠키**를 뽑아 `.env.b` 에 넣습니다 ([10절](#10-조회수등급-켜기-한-번만-하면-된다) 과 같은 방법)
4. 말투를 만듭니다. `node 설정.mjs` 로 만든 뒤 파일을 `계정/b/persona.json` 으로 옮기세요
5. 시각표를 켭니다
   ```bash
   cp 예시/com.example.threads.b.plist.예시 ~/Library/LaunchAgents/com.example.threads.b.plist
   launchctl load ~/Library/LaunchAgents/com.example.threads.b.plist
   ```

### 꼭 지켜야 할 것 셋

**① 미디어 폴더(`media/`)는 나누지 마세요.** 지금처럼 같이 쓰면 **같은 원글을 두 계정이
올리는 일이 없습니다.** 나눠 두면 같은 사진에 같은 레시피가 두 계정에 떠서 한 사람이
굴리는 게 바로 보입니다.

**② 올리는 시각을 엇갈리세요.** 본으로 드린 시각표가 이미 그렇게 돼 있습니다.

```
첫 계정   08 · 12 · 16 · 20 · 24시
둘째 계정 10 · 14 · 18 · 22 · 02시
```

**③ 말투를 진짜 다르게 하세요.** 복사해서 조금만 고치면 문장 결이 똑같이 나옵니다.
정체성·자주 쓰는 표현·**내 글 예시**를 아예 다른 사람으로 채워야 합니다.

> ⚠️ 같은 컴퓨터·같은 인터넷·같은 개발자 앱을 씁니다. 메타가 두 계정을 **한 사람 것으로
> 묶어 볼 수 있습니다.** 한쪽이 제재받으면 다른 쪽도 영향을 받을 수 있습니다.

## 11. 알아두면 좋은 것

**같은 글을 두 번 올리지 않는다.** 올린 글은 `media/쓴것/` 으로 옮겨져 다음부터 후보에서 빠진다.

**레시피가 없는 글은 자동으로 걸러진다.** 재료 분량이 3개 이상 적힌 글만 쓴다.
본문은 낚시만 하고 레시피는 작성자가 답글에 다는 경우가 많아, 답글까지 읽어서 판단한다.

**사진도 영상도 없는 글은 안 쓴다.** 볼거리가 없고 링크 미리보기도 못 막기 때문이다.

**비법 재료의 정체를 모르면 그 글을 안 쓴다.** 원글이 `킥소스` 처럼 별명으로만 부르고
정체를 자기 링크 뒤에 숨겨 둔 경우다. 정체를 알아낸 경우에는 별명을 그대로 두고
**링크 바로 위 소개 한 줄에서 밝힌다** — 궁금하게 두었다가 링크에서 풀어 준다.

**분량 단위를 친절하게 적는다.** 큰술은 `2T (큰술)`, 작은술은 `1t (작은술)` 처럼 씁니다.
`T` 는 15ml, `t` 는 5ml 로 **3배 차이**라, 원문에 적힌 쪽이 바뀌면 반드시 경고합니다.

**분량이 깨지면 알려 준다.** LLM 이 `1스푼` 을 `1스푤` 로 깨뜨린 적이 실제로 있다.
원문과 대조해서 이상하면 `⚠️ 원문에 없는 분량꼴이다` 라고 경고한다.

**스레드 한도.** 24시간에 게시물 250개, 답글 1,000개. 한 편이 본문 1 + 답글 2 정도를 쓴다.

**비용.** 글쓰기는 **클로드 유료 구독**으로 돈다. API 요금이 따로 안 나가는 대신 구독 사용량을 쓴다. 한도에 걸리면 그 판은 실패로 남고 아침 감시가 알려준다.

**저작권.** 남의 사진·영상을 그대로 받아 다시 올린다. 판단과 책임은 쓰는 사람에게 있다.

**하트·댓글과 답글은 그 계정의 말투로 나간다.** 「세팅」의 말투(정체성·말투·자주 쓰는 표현·내 글 예시)와
계정의 언어·분야를 보고 댓글을 짓는다. 말투를 고치면 댓글도 따라 바뀐다. 글에만 쓰는 항목(도입 유형·글 구조·레시피 형식)은 댓글에 안 쓴다.

**발행 토큰(THREADS_ACCESS_TOKEN)은 붙여넣지 않고 받는다.** 「세팅」 열쇠 칸의 **「자동발급」**을 누르면
크롬 창이 열린다. **그 계정으로** 로그인해 허용을 누르면 끝이다. 자동으로 안 되면 옆의 **「터미널로 받기」**를
누른다 — 관리자 도구로 넘어가 (처음이면 맥 비밀번호를 묻고) 터미널에 `threads-login.mjs` 가 저절로 쳐진다.
브라우저가 열리면 **그 계정으로** 로그인해 허용을 누르고, 바뀐 주소창 전체를 터미널에 붙여넣고 Enter.
「끝났다」가 뜨면 열쇠 파일에 들어간 것이다. 60일마다 다시 받는다. 관리자 도구 자체는
[11-1절](#11-1-관리자-도구--터미널원격-연결자동-업데이트)에서 자세히 다룬다.

## 11-1. 관리자 도구 — 터미널·원격 연결·자동 업데이트

옆바 맨 아래 **「관리자 도구」**를 누르면 세 가지가 한 화면에 모여 있다.

### 터미널

1. 옆바에서 「관리자 도구」를 누른다.
2. 이 맥의 **로그인 비밀번호**를 물으면 넣고 「열기」를 누른다. 비밀번호는 맥에게 맞는지 물어만 보고 어디에도 저장하지 않는다.
3. 맥 터미널 앱과 같은 검은 창이 뜬다. 「창 나누기」로 **넷까지** 나눌 수 있고, 창마다 따로 명령을 친다. 새로고침해도 창은 살아 있다.
4. 다 쓰면 **「잠그기」**를 누른다 — 창이 전부 닫히고 다음에 열 때 비밀번호를 다시 묻는다.

⚠️ 진짜 터미널이라 **파일을 지우는 명령도 막지 않는다.**

설정 화면 열쇠 칸의 **「터미널로 받기」**를 누르면 바로 이 터미널로 넘어와 `threads-login.mjs` 명령이
미리 쳐져 있다 — 비밀번호만 넣으면 곧장 실행된다.

### 원격 연결

제작자가 화면을 직접 봐야 도와줄 수 있을 때 쓴다.

1. 「크롬 원격 데스크톱 열기」를 누르면 새 창이 뜬다.
2. 거기서 **액세스 코드 생성**을 누르면 12자리 코드가 나온다.
3. 그 코드를 관리자 도구 화면 칸에 넣고 **「제작자에게 보내기」**를 누른다.
4. 코드는 **5분**만 유효하다. 못 보내지면(제작자 연락처가 안 채워졌거나 저쪽 설정 문제) 화면에
   코드가 크게 뜬다 — 그 코드를 문자·카톡 같은 다른 길로 직접 전한다.

제작자에게 코드가 갈 연락처는 `src/제작자.mjs` 에 **사용자가 직접** 채워 넣어야 한다. 비어 있으면
자동으로는 안 간다.

### 자동 업데이트

카드 위쪽에 지금 판·최신 판이 나온다.

- **「지금 확인」** — 새 판이 나왔는지 지금 바로 알아본다.
- **「지금 업데이트」** — 새 판이 있을 때만 보인다. 누르면 **1~2분** 걸리고 그동안 화면이 잠깐 끊긴다.
- **매일 11:00 에 저절로 확인** 스위치 — 켜 두면 매일 그 시각에 새 판이 있는지 저절로 본다.

업데이트가 실패하면 **저절로 예전 판으로 되돌리고 텔레그램으로 알린다.** 되돌리기까지 실패하는
아주 드문 경우에는, 알림에 적힌 `업데이트백업/<판 번호>/` 폴더를 손으로 제자리에 복사해야 한다.

**코드만 새로 받는다.** 아래는 업데이트해도 그대로 남는다.

- 열쇠 (`.env*`, 스레드 로그인 정보)
- 계정 폴더 통째로 (`계정/<계정이름>/`) — 출입증·말투·장부·사진이 다 그 안에 있습니다
- 크롬 프로필 (`크롬프로필/`)

## 11-2. 점검 로그 — 자동화가 잘 도는지 지켜보기

**점검 로그가 뭔가.** 프로그램이 30분마다 스스로 "계정마다 자동으로 글이 잘 올라가고 있나, 헬스체크·조회수 알리미 같은 뒷단이 켜져 있나"를 훑어보는 장치다.
**헬스체크** 는 프로그램이 안 죽었는지 스스로 확인하는 것, **알리미** 는 조회수가 오른 글을 텔레그램으로 알려 주는 것이다. 둘 다 발행과 별개로 도는 뒷단이다.
2026-08-28 에 발행은 멀쩡해 보였는데 뒤에서 조용히 셋이 고장 나 있던 일이 있었다 — 그걸 다시 안 겪으려고 만들었다.

### 어디서 보나

| 자리 | 뭐가 보이나 |
|---|---|
| 옆바 계정 카드의 **점** | 그 계정에 문제가 있으면 점이 뜬다. **빨강** = 급함, **노랑** = 봐두면 좋음 |
| 개요 화면 **「상태 체크」** 카드 | 지금 열려 있는 문제와 원인을 한 줄씩. **지켜보는 장치(점검·헬스체크·조회수 알리미)가 꺼져 있으면 맨 위에 빨갛게 알려 줍니다** — 목록이 비어 있는 것이 「괜찮다」인지 「안 재고 있다」인지 헷갈리지 않게 |
| **점검** 페이지 아래 **「점검 기록」** 카드 | 문제가 **생겼을 때**·**고쳐졌을 때**를 시간 순으로 쌓아 둔 기록 |

### 켜는 법 — 저절로 안 켜진다

1. 옆바에서 **「모니터링」**을 누른다.
2. **「점검」** 카드를 찾는다.
3. 스위치를 누른다. 기본은 **30분마다 한 번**이다.

이 스위치를 안 누르면 위 세 자리 어디에도 아무것도 안 뜬다. **처음 설치했다고 저절로 켜지지 않는다 — 반드시 사람이 직접 켜야 한다.**

### 텔레그램 알림 두 가지

| 언제 오나 | 무슨 뜻 |
|---|---|
| 문제가 **새로 생겼을 때** | 그 계정에 방금 이상이 발견됐다는 뜻. 원인이 함께 온다 |
| 문제가 **고쳐졌을 때** | 「돌아왔습니다」와 함께 온다. 더는 신경 안 써도 된다 |

**같은 문제로 알림이 계속 오지는 않는다.** 문제가 그대로면 다시 안 알린다 — 자는 동안 같은 알림이 쌓이지 않게 하기 위해서다.

### 빨간 줄(점)이 뜨면 어떻게 하나

1. 옆바 점이 뜬 계정을 누르거나, **점검** 페이지를 연다.
2. 문제 옆에 적힌 **원인 한 줄**을 읽는다. 자주 나오는 것들이다.

| 화면에 뜨는 말 | 무슨 뜻 · 무엇을 하면 되나 |
|---|---|
| 「출입증 파일이 없습니다 — 설정에서 이 계정 열쇠를 넣어 주세요」 | 설정 화면 열쇠 칸에 그 계정 키가 안 들어가 있다. 넣어 준다 |
| 「멈춤 스위치가 켜져 있습니다」 | 그 계정을 사람이 일부러 멈춰 놨다. 계속 멈춰 둘 거면 그대로 둬도 된다 |
| 「직전 발행과 너무 가까워 건너뛰었습니다」 | 맥이 자다 깨어나며 밀린 판을 건너뛴 것뿐이다. 다음 판에서 저절로 풀린다 |
| 「쓸 만한 글이 없었습니다」 | 그 시간대에 쓸 만한 원본 글이 없었을 뿐이다. 고장이 아니다 |
| 「출입증 권한이 모자랍니다 — 새로 받아야 합니다」 | [10절](#10-조회수등급-켜기-한-번만-하면-된다)처럼 로그인 정보를 다시 받아야 한다 |
| 「그 시각에 아예 안 떴습니다 — 예약이나 맥 잠자기를 확인하세요」 | 예약(launchd) 자체가 꺼졌거나 맥이 그 시각에 잠들어 있었을 수 있다. 관리자 도구 터미널에서 확인이 필요하면 제작자에게 원격 연결로 알린다 |
| 그 밖의 낯선 문장 | 로그에 찍힌 오류를 그대로 옮긴 것이다. 뜻을 모르겠으면 그 문장을 그대로 캡처해 제작자에게 보낸다 |

3. 급한 것(빨강)부터 본다. 노랑은 급하지 않으니 시간 날 때 봐도 된다.
4. 원인대로 고치고 나면 **다음 점검 판(최대 30분 안)**에 저절로 「돌아왔습니다」가 온다. 사람이 따로 "확인 눌러 끄기"를 할 필요는 없다.

## 12. 이럴 땐 이렇게

**등급이 전부 `알수없음` 이다**
→ [10절](#10-조회수등급-켜기-한-번만-하면-된다) 을 안 한 것이다. 쿠키를 넣는다.

**아무것도 안 올라가고 끝난다**
→ 후보가 전부 걸러진 것이다. `레시피 없는 글 N개 제외` 같은 줄이 떴을 것이다.
`TOP` 을 키우고(`TOP=15`) 검색어를 늘린다(`레시피 요리 한식`).

**`레시피 → 1개` 처럼 검색이 적게 잡힌다**
→ 스레드가 잠깐 조인 것이다. 몇 분 뒤에 다시 돌리면 된다.

**`링크 없음 — "OO" 에 로켓 상품이 없다`**
→ 로켓 배송 상품만 쓰기 때문이다. 링크 없이 글은 올라간다. `[광고]` 도 안 붙는다.

**`건너뜀 — 준비물에 "킥소스" 가 있는데 정체를 모른다`**
→ 원글이 비법 재료를 `킥소스` 같은 별명으로만 부르고 정체를 안 밝힌 것이다.
그대로 베끼면 우리 글에도 정체 모를 재료가 남아서 일부러 버린다. 다음 후보로 넘어간다.

**`⚠️ 원문에 없는 분량꼴이다`**
→ 분량이 깨졌을 수 있다. 올라간 글을 열어 재료 줄을 눈으로 확인한다.

**`⚠️ 사진이 없어 링크에 미리보기 카드가 붙었을 수 있다`**
→ 원본에 사진이 없어 카드를 못 막은 것이다. 신경 쓰이면 그 글은 보관 처리한다.

**토큰이 만료됐다는 오류**
→ 스레드 토큰은 60일마다 끊긴다. `node --env-file=.env.local threads-login.mjs` 를 다시 돌린다.

**글이 어색하다**
→ [8절](#8-말투-바꾸기)에서 `내 글 예시` 에 실제 글을 더 넣는다. 이게 제일 잘 듣는다.

## 13. 명령어 한눈에

```bash
cd ~/projects/coupas-auto                                          # 폴더로 이동

node --env-file=.env.local run.mjs 레시피 요리 한식                  # 보기만
node --env-file=.env.local run.mjs 레시피 요리 한식 --받기 --재구성    # 만들기만
node --env-file=.env.local run.mjs 레시피 요리 한식 --받기 --재구성 --발행   # 실제 발행

TOP=15 LIMIT=2 node --env-file=.env.local run.mjs 레시피 --받기 --재구성 --발행

node 설정.mjs                                    # 말투 다시 만들기
open -e ~/projects/coupas-auto/persona.json      # 말투 직접 고치기
open -e .env.local                               # 열쇠 고치기
./검사.sh                                    # 잘 도는지 검사
node --env-file=.env.local threads-login.mjs     # 토큰 재발급 (60일마다)

node --env-file=.env.local 글지우기.mjs <글 링크>   # 잘못 나간 글을 글타래째 지우기
```

### 잘못 나간 글 지우기

브라우저에서 그 글을 열고 주소창의 주소를 통째로 복사한 뒤 이렇게 한다.

```bash
node --env-file=.env.local 글지우기.mjs https://www.threads.com/@example.cook/post/DcZnzV-EcBL
```

**본문(첫 조각) 주소를 줘야 한다.** 그러면 레시피 답글까지 함께 지운다.
지울 글을 화면에 보여 주고 `지운다` 라고 적어야 실제로 지운다. 되돌릴 수 없기 때문이다.

`⛔ threads_delete 권한이 없다` 가 뜨면 토큰을 다시 받아야 한다 —
`threads-login.mjs` 를 돌리고 허용 화면에서 **「삭제」 항목까지 켠다.**
권한이 없어도 발행은 멀쩡히 돌아간다. 지우는 것만 웹 화면에서 손으로 하면 된다.

> **초록불을 완료의 증거로 삼지 않는다.** 검사가 전부 통과해도 실제 발행은 별개다.
> 한 편 올려서 눈으로 확인하는 단계를 건너뛰지 않는다.
