# 어필리 — 제휴마케팅 전담 에이전트 설계

작성 2026-09-01. 사용자 승인 절차를 거쳐 확정한 것만 적는다.

## 0. 왜 만드나

우리는 열 계정으로 매일 글을 올리지만 **그 글이 우리가 정한 규칙을 지켰는지 아무도 안 본다.**
요리팩(`src/분야/요리/한국어.mjs` 의 `레시피서식`)에 형식·규칙·첫 줄 훅 무게가 실측으로 적혀
있는데, 판이 돈 뒤에 **지켰는지 확인하는 고리가 없다.**

그리고 그 무게는 **2026-08 일본 조사(359글)와 2026-09-01 한국 조사(2,037글)로 한 번 잰 값**이다.
트렌드는 움직이는데 값은 안 움직인다.

어필리가 이 둘을 맡는다 — **매일 지켰는지 보고, 주마다 다시 재서 고치자고 제안한다.**

## 1. 사용자가 정한 것 — 재논의 금지

| 항목 | 값 | 언제 |
|---|---|---|
| 이름 | **어필리** (affiliate) | 2026-09-01 |
| 감독 시점 | **매일 오전 8시.** 전날 글을 모아 준수도와 인사이트를 텔레그램으로 | 2026-09-01 |
| 반영 방식 | **제안만 하고 사람이 승인.** 자동 반영 없다 | 2026-09-01 |
| 학습 주기 | **주 1회 · 한국 + 일본** | 2026-09-01 |
| 판단 주체 | **숫자는 코드가 재고, 해석만 어필리가 한다** (접근법 B) | 2026-09-01 |

**발행을 막지 않는다.** 어필리는 사후에만 본다. 올리기 직전에 끼어들어 글을 막는 길은
검토했고 **선택하지 않았다** — 잘못 막으면 그 계정이 그날 한 편도 못 올린다.

## 2. 어필리는 파일 하나다

`.claude/agents/어필리.md` — 앞머리에 설정(이름·설명·모델), 본문에 지침.

**한 파일이 두 곳에서 쓰인다.**

| 어디서 | 어떻게 |
|---|---|
| 대화 중 | 클로드가 Agent 도구로 부른다. 이때는 도구를 쓸 수 있다 (사람이 지켜본다) |
| 예약 | `claude -p --append-system-prompt-file .claude/agents/어필리.md --allowedTools ""` |

⚠️ **예약에서 어필리는 도구를 안 쓴다.** 필요한 자료는 전부 프롬프트로 받는다.
까닭 둘 — ① 도구를 쓰게 하면 매번 다른 경로로 돌아 결과가 재현되지 않는다
② 자동으로 도는 것에 파일 접근을 주면 사고 범위가 넓어진다.

## 3. 매뉴얼의 정본은 팩이다 — 문서를 새로 만들지 않는다

`docs/제휴-매뉴얼.md` 같은 문서를 따로 쓰면 **팩과 두 벌이 되어 언젠가 어긋난다.**
이 저장소가 이미 겪은 실패다 ([[계정마다-복사본을-두면-아무도-못-고친다]]).

**정본은 `레시피서식`(팩)이다.** 사람이 읽을 문서는 팩에서 뽑아 만든다 —
`도구.매뉴얼뽑기.mjs` 가 `docs/제휴-매뉴얼.md` 를 **덮어쓴다.** 문서를 손으로 고치지 않는다.
문서 맨 위에 「이 파일은 자동으로 만들어진다. 고치려면 팩을 고쳐라」를 적는다.

## 4. 매일 감독 — `제휴감독돌기.mjs`

### 4-1. 흐름

```
① 어제 올린 글을 뽑는다            성적 장부(계정/*/글성적장부.json)의 올린때로 고른다
② 스레드에서 그 글을 다시 읽는다    src/threads.mjs 의 상세(계정, code) — 본문 + 글타래
③ 채점한다                        src/제휴채점.mjs — 순수 계산. 판정을 지어내지 않는다
④ 일주일 전 글의 성과를 가른다      훅 유형별 조회수 중앙값 + 표본 수
⑤ 어필리에게 ③④ 표를 넘긴다        claude -p (도구 없음)
⑥ 텔레그램으로 보낸다              src/알림.mjs 의 알리고찍기
```

**②를 하는 까닭.** 우리가 만든 글이 아니라 **실제로 올라간 글**을 봐야 한다.
답글이 권한 문제로 죽거나 본문이 잘렸을 수 있다. 만든 것을 채점하면 그 사고가 안 보인다.

### 4-2. 시계가 둘인 까닭

**어제 올린 글은 조회수가 덜 쌓였다.** 그래서 물음을 둘로 가른다.

| 무엇을 | 어느 글로 | 왜 |
|---|---|---|
| **매뉴얼을 지켰나** | **어제 글** | 형식은 올린 즉시 잴 수 있다 |
| **무엇이 통했나** | **7일 전 글** | 조회수가 충분히 쌓인 뒤라야 견줄 수 있다 |

### 4-3. 채점 항목 — 기계로 잴 수 있는 것만

`레시피서식` 이 정한 것 가운데 **다툼 없이 잴 수 있는 것**만 채점한다.

| 항목 | 어떻게 재나 | 지킴 기준 |
|---|---|---|
| 본문 길이 | 빈 줄 뺀 줄 수 | 4~5줄 |
| 본문 이모지 | 개수와 자리 | 맨 끝에 하나 |
| 본문에 링크 | `http` 포함 여부 | **없어야 한다** (한국 실측 상위 60편 중 0편) |
| 첫 줄 훅 | 유형별 낱말표 대조 (아래 ⚠️) | 어느 유형인지. **못 가리면 「분류 안 됨」** |
| 답글 있나 | 글타래 길이 | 1개 이상 |
| 답글 머리 | `🛒`·`준비물`·`만드는 법` 포함 | 있어야 한다 |
| 번호 이모지 | `1️⃣` 따위 | 있어야 한다 |
| 재료 분량 | 숫자+단위 개수 | 3개 이상 (팩의 `숫자최소`) |
| 답글 길이 | 줄 수 | 25줄 이내 |
| 광고 표기 | `[광고]` 위치 | 답글 안에 있다 |

⚠️ **훅 분류는 채점기가 제 낱말표로 한다.** 팩의 `도입 유형` 은 「나도 안 믿었는데 해보니
됐다는 투로 연다」처럼 **사람(과 글 짓는 클로드)에게 주는 지시문**이라 기계가 못 읽는다.
그래서 `src/제휴채점.mjs` 가 유형마다 낱말표를 따로 갖는다.

**두 벌이 되는 것을 검사가 막는다.** `test.제휴채점.mjs` 가 팩의 `도입 유형` 개수·차례와
낱말표의 짝이 맞는지 본다. 팩에 유형을 더하고 낱말표를 안 더하면 **빨간불이 난다.**
짝을 못 맞춘 채 도는 것이 가장 위험하다 — 새 훅이 늘 「분류 안 됨」으로 세어져
그 훅이 통하는지 영영 모르게 된다.

⚠️ **못 가린 것은 「지킴」도 「어김」도 아니다.** 「분류 안 됨」으로 따로 센다.
틀린 판정을 내느니 모른다고 한다 (CLAUDE.md §2-2 「추출 실패 시 조용히 숨긴다」).

### 4-4. 문턱이 둘이다 — 헷갈리면 안 된다

| 문턱 | 몇 편 | 무엇을 막나 |
|---|---|---|
| **순위 문턱** | 5편 | 그 훅 유형을 **리포트 순위에 안 넣는다.** 「표본 부족」으로 찍는다 |
| **제안 문턱** | 30편 | 그 근거로 **팩을 고치자는 제안을 못 만든다** (§6) |

보여주는 것보다 **고치는 것의 문턱이 훨씬 높다.** 리포트는 틀려도 사람이 읽고 넘기지만,
팩을 고치면 열 계정의 모든 글이 바뀐다.

### 4-5. 순위는 중앙값으로 낸다

평균이 아니라 **중앙값**을 쓴다. 배수를 적을 때는 **분자의 편수를 괄호에 함께** 적는다.

까닭 — 오늘(2026-09-01) 평균으로 재서 1위였던 훅이 중앙값으로는 4위였다
([[평균-한-편이-끌면-순위가-뒤집힌다]]).

### 4-6. 텔레그램 글의 꼴

```
📊 어필리 · 2026-09-02

어제 8편 올렸다. 매뉴얼 준수 6/8.
  ⚠️ sample_salim DcxYz — 본문에 링크가 들어갔다
  ⚠️ sample.unni DcaBc — 답글에 재료 분량이 1개뿐 (3개 필요)
  분류 안 됨 1편 (첫 줄 훅)

7일 전 12편의 성적 —
  「남이 먼저 물어봤다」  4편  조회 중앙값 1,240
  「나도 안 믿었는데」    3편  조회 중앙값   890
  나머지 유형은 표본 부족

[어필리]
(여기에 한 문단)
```

## 5. 주간 학습 — `제휴학습돌기.mjs`

일요일 새벽. 2026-09-01 에 손으로 한 조사를 그대로 자동화한다.

```
① 낱말로 검색해 글을 걷는다        src/threads.mjs 의 검색()
② 그 계정들의 프로필을 읽는다      프로필읽기() — 팔로워 + 최근 글
③ 첫 줄 유형별 비율을 센다         퍼진 글 vs 평소 글 (대조군)
④ 계정/_전체/제휴학습/날짜.json 에 쌓는다
⑤ 지난 4주 기록과 함께 어필리에게 넘겨 제안서를 받는다   매일 감독과 같다 — 도구 없이, 자료는 프롬프트로
```

**한국과 일본을 각각 돈다.** 언어팩 기준은 CLAUDE.md §3 을 따른다 —
일본어 낱말은 번역이 아니라 **그 언어 사용자가 실제로 쓰는 말**로 짠다.

## 6. 제안은 사람이 누른다 — `계정/_전체/제휴제안.json`

어필리가 쓰는 제안 하나의 꼴.

```json
{
  "낸때": "2026-09-07T19:00:00.000Z",
  "어디": "요리/한국어 · 도입 유형 · 비밀·감춤",
  "지금": 3.7,
  "바꾸자": 4.2,
  "근거": "이번 주 표본 31편 · 지난 4주 누적 96편 · 중앙값 배수 4.1",
  "표본": 31,
  "상태": "기다림"
}
```

**제안을 낼 수 있는 문턱 — 표본 30편 이상.** 코드가 막는다. 어필리가 아무리 확신해도
30편 미만이면 제안 자체가 안 만들어진다.

대시보드 「어필리」 화면에서 누르면 `상태` 가 `받음` 이 되고 **팩 파일이 바뀐다.**
안 누르면 아무 일도 없다. 물리치면 `물림` 으로 적고 까닭을 남긴다.

## 7. 만들 파일

| 파일 | 무엇 |
|---|---|
| `.claude/agents/어필리.md` | 어필리 지침서 (대화·예약이 함께 쓴다) |
| `src/제휴채점.mjs` | 채점 규칙. **순수 계산** — 파일도 통신도 안 건드린다 |
| `src/제휴제안.mjs` | 제안 읽기·쓰기·받기. 문턱 30편을 여기서 지킨다 |
| `제휴감독돌기.mjs` | 매일 8시 몸통 |
| `제휴학습돌기.mjs` | 주 1회 몸통 |
| `어필리.sh` | 예약이 부르는 껍데기 (성적.sh 와 같은 꼴) |
| `도구.매뉴얼뽑기.mjs` | 팩 → `docs/제휴-매뉴얼.md` |
| `test.제휴채점.mjs` | 채점 검사 |
| `test.제휴제안.mjs` | 문턱·승인 검사 |
| `dashboard/app/(pages)/affili/` | 제안 승인 · 지난 리포트 |
| plist 둘 | `com.threads.affili.daily` · `com.threads.affili.weekly` |

**계정별로 돌지 않는다.** 하루에 리포트 한 통이다 — 열 통이 오면 아무도 안 읽는다.

## 7-1. 두 단계로 나눠 만든다

파일 열하나를 한꺼번에 만들지 않는다. **1단계가 혼자서도 쓸모 있어야** 한다.

| 단계 | 무엇 | 끝났다는 증거 |
|---|---|---|
| **1단계 — 매일 감독** | `src/제휴채점.mjs` · `제휴감독돌기.mjs` · `어필리.sh` · `.claude/agents/어필리.md` · `test.제휴채점.mjs` · plist 하나 | **사람이 손으로 한 판 돌려 텔레그램을 받아 본다.** 초록불은 증거가 아니다 (CLAUDE.md §2-5) |
| **2단계 — 주간 학습·제안** | `제휴학습돌기.mjs` · `src/제휴제안.mjs` · `test.제휴제안.mjs` · 대시보드 화면 · plist 하나 · `도구.매뉴얼뽑기.mjs` | 제안 하나를 실제로 눌러 팩이 바뀌는 것을 본다 |

1단계를 돌려 보고 **채점이 헛짚는 곳이 있으면 2단계 전에 고친다.** 헛짚는 채점기로
팩을 고치자는 제안을 내면 잘못이 굳는다.

**두 단계 모두 만든 뒤 검수 에이전트를 붙인다** — 매일 도는 길을 건드리는 일이다.
이 저장소에서 세 번 붙여 세 번 다 결함이 나왔다.

## 8. 어긋났을 때

| 무엇이 | 어떻게 |
|---|---|
| 어필리(claude)가 죽는다 | **채점표만 보낸다.** 해석 자리에 「어필리가 답을 못 했다」를 적는다 |
| 스레드에서 글을 못 읽는다 | 그 글은 「못 읽음」으로 세고 채점에서 뺀다. 통째로 멈추지 않는다 |
| 어제 올린 글이 0편 | 준수도 절을 통째로 빼고 성과 절만 보낸다 |
| 성적 장부가 깨졌다 | 그 계정만 건너뛴다. 나머지 계정은 돈다 |
| 텔레그램이 안 간다 | `알리고찍기` 가 이미 기록을 남긴다. 로그에 남기고 종료코드를 더럽힌다 |

**멈춤 스위치를 보지 않는다.** 멈춤은 「글을 올리지 마라」이지 「보지 마라」가 아니다
(성적.sh 와 같은 판단).

## 9. 검사

- `test.제휴채점.mjs` — 채점 항목마다 지킴/어김/분류 안 됨 세 갈래를 확인한다.
  **일부러 어긴 글을 넣어 빨간불이 나오는지 본다** ([[가드-검사도-일부러-어겨-봐야-믿을-수-있다]])
- `test.제휴제안.mjs` — 표본 29편이면 제안이 안 만들어지는지, 승인이 팩을 제대로 바꾸는지
- 둘 다 `./검사.sh` 가 자동으로 집는다 (`test.*.mjs` 를 훑는다)
- **검사는 실서버에 쓰기를 보내지 않는다.** 임시 폴더에서만 돈다
  ([[검사가-실서버-장부를-쓰면-안-된다]])
- **plist 검사는 가짜 실행기를 넘긴다** ([[검사가-진짜-launchd에-유령-예약을-남긴다]])

## 10. 안 하는 것 (YAGNI)

- **발행 전 차단** — 사용자가 사후 리포트를 골랐다
- **자동 반영** — 사용자가 사람 승인을 골랐다
- **영어권 학습** — 주 1회 한국·일본만. 영어는 계정이 자리 잡은 뒤에
- **뷰티팩 채점** — 요리팩만. 뷰티는 `말투서식` 이 아직 `null` 이다
- **어필리에게 도구 주기(예약 경로)** — 재현성과 사고 범위 때문에

## 11. 아직 모르는 것

- **어제 올린 글을 8시에 스레드에서 읽을 때 조회수가 0으로 나올 수 있다.** 준수도는 조회수를
  안 쓰므로 문제없지만, 실제로 그런지 만들면서 한 판 돌려 확인한다
- **주간 학습 한 판이 얼마나 걸리는지** 모른다. 손으로 했을 때 한국만 20분쯤이었다.
  일본을 더하면 40분 안팎으로 본다. 넘치면 낱말 수를 줄인다
- **제안이 팩 파일을 고치는 방식** — 무게 숫자 하나를 바꾸는 것이라 정규식으로 될 것 같지만,
  만들 때 팩 구조를 다시 보고 정한다. 실패하면 고치지 않고 사람에게 알린다
