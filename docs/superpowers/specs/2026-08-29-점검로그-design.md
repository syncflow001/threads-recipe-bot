# 점검 로그 — 자동화가 제대로 도는지 스스로 지켜보고, 이상을 한곳에 모은다

작성 2026-08-29 · 사용자와 합의한 설계. **§1 결정 사항은 재논의하지 않는다.**

---

## 0. 왜 만드나

2026-08-28 하루에 **조용한 고장 셋**을 겪었다. 셋 다 발행은 멀쩡해 보였고 아무 경보도 안 울렸다.

| 무엇 | 어떻게 알았나 | 몰랐으면 |
|---|---|---|
| 검사가 진짜 launchd 에 유령 예약을 남기고 진짜 예약을 내렸다 | 사람이 실행 직전에 눈으로 봤다 | 20:02 발행이 안 떴다 |
| 글 기록에 옛 계정 이름이 박혀 성적·도달이 통째로 멈췄다 | 사람이 「다 끝났나」 물어 훑다가 | 계속 몰랐다 |
| 헬스체크·조회수 알리미가 **아예 안 켜져 있었다** | 이 설계를 위한 조사 중에 | 계속 몰랐다 |

공통점 하나 — **아무도 「이 자동화가 지금 돌고 있나」를 안 보고 있었다.** 발행 결과만 봤다.

이 문서는 그것을 보는 장치를 정의한다.

## 1. 결정 사항 — 재논의 금지

| 항목 | 값 | 왜 |
|---|---|---|
| 점검 주기 | **30분마다 한 번, 전 계정을 훑는다** | 예약 하나로 끝난다. 발행 간격이 최소 두세 시간이라 30분 지연은 실害가 없다 |
| 알릴 기준 | **예정 시각에 글이 안 올라갔으면 이유 불문 알린다.** 원인을 함께 적는다 | 사용자 결정 |
| 알림 반복 | **상태가 바뀔 때만.** 문제 생길 때 한 번, 고쳐지면 「돌아왔습니다」 한 번 | 자는 동안 같은 알림이 쌓이면 무뎌진다 |
| 보이는 자리 | **옆바 계정 카드 빨간 점** · **개요 「상태 체크」 카드** · **점검 페이지 「점검 기록」** | 개요 맨 위 배너는 **뺀다**(사용자 결정) |
| 얻는 방식 | **밖에서 훑어본다.** 점검기가 흔적(로그·장부·launchd)을 읽어 판정한다. 자동화 코드는 안 건드린다 | 「아예 안 떴다」를 잡을 수 있는 유일한 길이다. 2026-08-28 사고가 정확히 그 경우였다 |
| 점검기의 권한 | **읽기만 한다. 무엇도 켜거나 끄지 않는다** | 교훈 「검사-초록이어도-단추는-사람이-누른다」. 자동으로 켜면 그것이 다음 사고다 |
| 길들이기 | **켜져 있는데 안 돌 때만** 이상으로 본다. 「켜야 하는데 안 켰다」로는 안 본다 | 사용자 결정 |
| 길들이기 언어 | **모든 계정이 쓴다.** 계정에 설정된 언어·분야대로 돈다 | 사용자 결정. 한국 계정도 키우려면 필요하다 |

## 3. 무엇을 점검하는가

계정마다 아래를 잰다. 판정은 셋 — **정상 / 이상 / 확인 못 함**. 「확인 못 함」을 「이상」과 섞지 않는다(이 저장소의 기존 관례, `왜안올라갔나.tsx` 의 `됨: true|false|null`).

| # | 갈래 | 무엇을 보나 | 이상 판정 |
|---|---|---|---|
| 1 | `예약살았나` | plist 가 있는 라벨이 **실제로 launchd 에 올라가 있나** | 파일은 있는데 안 올라감 |
| 2 | `있어야할것` | 자동발행·성적(전 계정) · 헬스체크·알리미(전체 하나씩) | plist 자체가 없음 |
| 3 | `켜뒀는데안돎` | **길들이기**가 켜져 있는데 흔적이 안 늘어남 | 간격(3h)의 **3배**가 지나도록 흔적 없음 |
| 4 | `발행` | 예정 시각이 지났는데 그 판의 흔적이 없거나 실패 | 아래 §3-1 |
| 5 | `마지막으로돈때` | 성적(6h)·감시(1일) 이 제 간격의 **3배**가 지나도록 흔적 없음 | 위와 같은 잣대 |
| 6 | `열쇠` | `헬스체크결과.json` 의 `탈` 배열 | 비어 있지 않음. 파일이 없으면 #2 가 이미 잡는다 |

**「간격의 3배」로 잡는 이유.** 맥이 자면 판이 밀린다. 두 판 놓친 것은 흔한 일이고 세 판은 아니다. 실측으로 오탐이 나면 이 배수만 고친다.

### 3-1. 발행 판정

이미 있는 `발행격자(계정, {뿌리})`(`src/대시보드.mjs:463`)를 그대로 쓴다. 예정 시각(plist)과 실제 판(`logs/<계정>-YYYY-MM.log` 의 `═══` 머리글)을 견줘 칸마다 상태를 준다.

| 격자 상태 | 로그 표시 | 점검 판정 |
|---|---|---|
| `올림` | `✅` | 정상 |
| `실패` | `‼️` | **이상** |
| `기록없음` | (아무 줄도 없음) | **이상** |
| `건너뜀` | `⏸` | **이상** — 사용자가 「이유 불문」을 골랐다. 원인에 「멈춤 스위치가 켜져 있다」를 적는다 |
| `못올림` | `⏭` | **이상** — 원인에 「쓸 만한 글이 없었다」를 적는다 |

⚠️ **알려진 구멍 하나.** `자동발행.sh:34` 의 `‼️ 열쇠 파일이 없습니다` 는 `═══` 머리글보다 **먼저** 찍혀서 격자 파서가 그 판을 아예 못 잡는다. 그래서 `기록없음`(빈칸)으로만 보인다. 이 설계에서는 **원인을 찾을 때 로그 꼬리를 함께 읽어** 이 문자열이 있으면 원인에 그대로 적는다. `자동발행.sh` 는 안 고친다(엔진 불변 원칙).

### 3-2. 원인을 어떻게 적는가

이상마다 **사람이 읽는 한 줄**을 붙인다. 재료는 로그 꼬리에서 찾는다.

| 로그에서 찾은 것 | 적을 원인 |
|---|---|
| `‼️  열쇠 파일이 없습니다` | 「출입증 파일이 없습니다 — 설정에서 이 계정 열쇠를 넣어 주세요」 |
| `⏸  멈춰 있습니다` | 「멈춤 스위치가 켜져 있습니다」 |
| `⏸  이번 판은 건너뜁니다` | 「직전 발행과 너무 가까워 건너뛰었습니다」 |
| `⏭  올린 글이 없습니다` | 「쓸 만한 글이 없었습니다」 |
| `⛔ 이 계정은 아직 못 돌립니다` | 「분야·언어·제휴 조합이 아직 없습니다」 |
| `‼️  스레드가 허락한 권한이 모자라` | 「출입증 권한이 모자랍니다 — 새로 받아야 합니다」 |
| `‼️  이번 판이 실패했습니다` | 그 줄을 그대로 |
| 아무 줄도 없음 | 「그 시각에 아예 안 떴습니다 — 예약이나 맥 잠자기를 확인하세요」 |

목록에 없는 `‼️` 줄은 **그 줄을 그대로** 적는다. 모르는 것을 「알 수 없음」으로 덮지 않는다.

## 4. 부품

### 4-1. `src/점검.mjs` (신설) — 판정

순수 함수를 최대한 분리해 검사 가능하게 만든다.

```js
// 한 계정을 재서 이상 목록을 돌려준다. 파일을 안 쓴다 — 읽기만 한다
export async function 계정점검(계정, { 뿌리, 지금, 실행, 런치폴더 })
//  → [{ 갈래, 무엇, 원인, 심각도, 열쇠 }]
//    갈래: '예약살았나'|'있어야할것'|'켜뒀는데안돎'|'발행'|'마지막으로돈때'|'열쇠'
//    심각도: '높음'|'보통'
//    열쇠: 같은 문제를 알아보는 값. 예 `발행:2026-08-29 20:02` — 상태 견주기에 쓴다

export function 원인찾기(로그꼬리)          // 순수. §3-2 표대로 한 줄을 돌려준다
export function 늦었나(마지막때, 간격초, 지금, 배수 = 3)  // 순수
export function 견주기(옛문제들, 새문제들)   // 순수. → { 생김: [...], 고쳐짐: [...] }
```

`실행`(execFile)·`런치폴더`를 **반드시 주입받는다.** 기본값을 안 넘기면 임시 폴더에서 진짜 `launchctl` 을 부르는 사고가 난다 — 2026-08-28 에 실제로 났다. `도구.첫계정이름붙이기.mjs` 의 `실행고르기()` 와 같은 안전장치를 둔다.

**예약이 살았나 재는 법** — `launchctl print gui/<uid>/<라벨>` 의 종료 코드. 0 이면 올라가 있다. plist 파일 존재만으로는 못 잡는다(현재 코드는 파일만 본다).

### 4-2. `점검돌기.mjs` (뿌리, 신설) — 30분마다 도는 몸통

`감시돌기.mjs` 와 같은 꼴. 계정을 훑어 `계정점검()` 을 부르고, 결과를 견줘 기록하고 알린다.

```
전 계정 반복 —
  새문제 = 계정점검(계정)
  옛문제 = 점검상태.json[계정]
  { 생김, 고쳐짐 } = 견주기(옛문제, 새문제)
  생김·고쳐짐 을 점검기록.<계정>.jsonl 에 이어붙인다
  생김·고쳐짐 이 있으면 텔레그램 한 통
점검상태.json 을 새것으로 안전쓰기
```

### 4-3. 파일 둘

**`점검상태.json`** (뿌리) — 지금 열려 있는 문제. 상태 견주기에만 쓴다.
```json
{ "example.cook": [{ "갈래": "발행", "열쇠": "발행:2026-08-29 20:02", "무엇": "...", "원인": "...", "심각도": "높음", "처음본때": "2026-08-29T20:12:00Z" }] }
```
`src/장부쓰기.mjs` 의 `안전쓰기` 로 원자적으로 쓴다.

**`점검기록.<계정>.jsonl`** — 이력. 한 줄씩 이어붙인다(`활동장부.<계정>.jsonl` 관례).
```json
{"때":"2026-08-29T20:12:00Z","일":"생김","갈래":"발행","무엇":"20:02 판이 안 올라갔습니다","원인":"쓸 만한 글이 없었습니다","심각도":"보통"}
{"때":"2026-08-30T08:12:00Z","일":"고쳐짐","갈래":"발행","무엇":"20:02 판이 안 올라갔습니다"}
```

**자르는 장치를 처음부터 넣는다.** 판마다 파일을 훑어 **30일 넘은 줄과 500줄 초과분**을 버린다. 지금 `활동장부.<계정>.jsonl` 에는 자르는 장치가 없어 무한정 자라고 있다 — 같은 실수를 되풀이하지 않는다.

### 4-4. 알림

기존 `src/알림.mjs` 의 `알리기(글, { 종류, 잠잠시간 })` 를 쓴다. **`잠잠시간: 0`** 으로 준다 — 반복 억제는 우리가 상태 견주기로 이미 하고 있어서, 잠잠시간까지 걸면 「고쳐짐」 알림이 눌릴 수 있다.

종류는 `점검-<계정>` 꼴. 한 계정의 생김·고쳐짐을 **한 통에 묶어** 보낸다 — 계정 여덟이 동시에 터져도 여덟 통이지 마흔 통이 아니다.

### 4-5. launchd

`com.threads.inspect`, `StartInterval` 1800초. `com.threads.watch` plist 를 본떠 만든다. **`점검켜기()`/`점검끄기()`** 를 `src/대시보드.mjs` 의 `간격시각표켜기` 꼴로 더하고, 화면(모니터링 쪽)에서 켜고 끈다. **사용자가 화면에서 켠다 — 설치 과정이 자동으로 켜지 않는다.**

## 6. 함께 고치는 것 — 계정이 안 실린 자리들

이번 일의 뿌리는 「계정 이름이 가야 할 곳에 안 갔다」이다. 조사에서 나온 같은 뿌리의 것들을 함께 고친다.

| 무엇 | 지금 | 고친 뒤 |
|---|---|---|
| **막힌 글** | `막힌글들(뿌리)` 가 계정을 안 받는다. 모든 계정이 같은 목록을 본다. 파일에 계정 표시조차 없다 | 막을 때 계정을 함께 적고, 화면은 그 계정 것만 |
| **사진 저장 자리** | 같은 원인. `계정진단` 이 뿌리를 계정별로 안 바꿔 첫 계정 `media/` 만 본다 | 계정별 `media/<계정>/` 을 본다 |
| **돌려본 기록** | `상태통.기록` 이 통 하나. 새 판이 앞 기록을 **지운다**. A 를 돌린 뒤 B 화면을 열면 A 것이 보인다 | 계정마다 한 통 |
| **「지금 돌고 있음」 잠금** | 통 하나 | **그대로 둔다.** 이것이 「한 번에 한 계정만」을 지킨다. 쪼개면 두 계정이 같은 크롬을 동시에 조종한다(2026-08-26 실제 사고) |
| **길들이기 안내 문구** | `활동설명.tsx:7` 「이 계정은 한국어라 길들이기는 안 해도 돼요」 | 모든 계정이 쓴다는 안내로. **엔진은 안 고친다** — 이미 한국어를 지원한다 |

### 6-1. 상태통 새 꼴

```js
export const 상태통 = {
  도는중: null,          // { 아이, 계정 } — 하나뿐. 잠금 겸 「멈추기」 손잡이
  계정별: {},            // { <계정>: { 기록: [], 진행: null, 마지막결과: null } }
  샘플도는중: false, ... // 나머지 잠금들은 그대로
}
```

「이미 돌고 있습니다」 거절 문구에 **어느 계정이 돌고 있는지**를 함께 준다.

## 7. 검사

- **모든 검사는 임시 폴더에서만 논다.** 실제 뿌리·`~/Library/LaunchAgents`·진짜 launchd·스레드·텔레그램을 절대 안 부른다. `실행`·`런치폴더`·`fetch` 를 전부 주입한다.
- 검사 전후로 `launchctl list | grep threads` 를 찍어 **차이가 없는 것**을 증거로 남긴다(2026-08-28 사고 재발 방지).
- 순수 함수(`원인찾기`·`늦었나`·`견주기`)는 단위 검사로 촘촘히 — §3-2 표의 줄마다 하나씩.
- 통합 검사: 임시 뿌리에 가짜 로그·plist·장부를 깔고 `계정점검()` 이 §3 표대로 판정하는지. 두 판을 이어 돌려 **「생김 → 고쳐짐」이 기록에 남는지**.
- 자르는 장치: 501줄을 넣고 500줄로 잘리는지, 31일 된 줄이 버려지는지.

## 8. 일부러 안 하는 것

- **도달을 정기적으로 재는 자동화** — 지금 없다. 이 설계는 「없다」는 것을 **알려 주기만** 한다. 새로 만드는 것은 다음 일이다.
- **점검기가 무엇을 자동으로 켜는 것** — 절대 안 한다. §1 결정.
- **점검 구멍을 메우려고 엔진을 고치기** — 안 한다. 「열쇠 파일 없음」이 격자에 안 잡히는 구멍도 `자동발행.sh` 를 고치지 않고 로그 꼬리를 읽어 우회한다.
  (§6 「막힌 글에 계정 적기」가 `run.mjs:374` 를 고치는 것은 이 금지에 안 걸린다 — 점검 구멍이 아니라 §6 이 시킨 일이다.)
- **개요 맨 위 배너** — 사용자가 뺐다.
- `활동장부.<계정>.jsonl` 에 자르는 장치 더하기 — 이번 범위 밖. 새로 만드는 `점검기록` 에만 넣는다.

## 9. 성공 기준

1. 점검기를 켜면 **첫 판에** §2 표의 이상들이 잡힌다 — 헬스체크 꺼짐 · 알리미 꺼짐 · 성적 넷 빠짐.
2. 예약 하나를 손으로 내려 보면(`launchctl bootout`) 30분 안에 `예약살았나` 이상이 뜨고 텔레그램이 온다. 되살리면 「돌아왔습니다」가 온다. **그 사이 다른 알림은 안 온다.**
3. 계정 A 를 돌린 뒤 계정 B 화면을 열면 **B 의 기록이 보인다**(지금은 A 것이 보인다).
4. 한국어 계정 점검 화면의 「막힌 글」에 **다른 계정 글이 안 보인다.**
5. 검사 전후로 진짜 launchd 예약 수가 그대로다.
