# 세션 2026-08-30 — 계정 격리

전날(08-29) 밤에 시작한 「계정 하나 = 폴더 하나」 개편을 이어받아, **한 판이 도는 동안
남의 계정을 침범하지 않는가**를 갈래마다 실측하고 남은 구멍을 막았다.

## 한 일

**계정이 섞이는 것을 막는 문을 셋으로 정리했다.**

| 문 | 무엇을 막나 | 언제 세웠나 |
|---|---|---|
| **파일** | 남의 장부를 읽거나 덮는 것 | 08-29 (계정길 하나 + 소스 검사) |
| **토큰** | 남의 계정으로 **글이 올라가는** 것 | **08-30 (오늘)** |
| **브라우저** | 남의 홈을 길들이거나 걷는 것 | 08-29 밤 |

**오늘 막은 것 — 토큰벽.** 쿠키에는 벽이 있었는데 토큰에는 없었다. 열쇠 파일에 남의 토큰이
들어가면 스레드 API 가 **그 계정으로 글을 올린다** — 되돌리기 가장 어려운 침범이다.
`run.mjs` 발행 길에 `토큰벽(계정)` 을 걸었다. 원래 계정 번호를 물어보던 요청 하나에
주인 아이디까지 함께 받아 오므로 **호출이 늘지 않는다.**

**같이 잡은 잠재 사고 — 계정 번호 캐시가 모듈에 하나뿐이었다.** 한 프로세스에서 두 계정을
다루면 먼저 물어본 번호가 뒤 계정에도 쓰였다. 실측으로 확인했다(B 토큰에 A 번호가 나왔다).
지금은 계정마다 프로세스가 따로라 안 터졌을 뿐이다. 토큰마다 따로 담게 했다.

**열쇠를 둘로 갈랐다.** `sample.unni` 파일에만 공용 열쇠(쿠팡·OPENAI) 사본이 남아 있었다.

## 결정 (왜 그렇게 했나까지)

**`--env-file` 순서를 실측으로 다시 쟀다.** 코드 주석의 「이미 있는 변수를 안 덮어쓴다」는
**부모 프로세스 환경**에 대한 이야기이고, `--env-file` 끼리는 **뒤에 오는 것이 이긴다.**
자동발행은 `.env.local` 다음에 계정 파일을 주므로 계정 파일 사본이 공용 값을 덮는다.
값 셋이 우연히 같아서 안 터지고 있었다 — 지문으로 대조해 확인한 뒤 치웠다.

**벽은 셋 다 「주인을 못 읽으면 안 막는다」.** 스레드가 화면 꼴을 바꾸면 벽이 모든 활동을
통째로 세운다. 그건 사고를 막는 게 아니라 프로그램을 죽이는 것이다. 대신 기록에 남긴다.

**벽을 자리마다 손으로 붙이지 않았다.** 그게 구멍이 생긴 이유다. `addCookies` 를 부르는 파일은
반드시 `계정이름으로벽` 도 불러야 한다는 것을 **소스를 읽는 검사**로 못 박았다.
계정 열쇠 파일에 공용 열쇠 이름이 있으면 빨간불이 되는 검사도 붙였다.

## 알게 된 것

**전수 실측 — 아홉 갈래가 모두 계정별로 갈렸다.**

| 갈래 | 자리 |
|---|---|
| 토큰·쿠키 | `계정/<이름>/열쇠.env` |
| 보관함 · 말투 · 미디어지문 · 쓴 글 | `계정/<이름>/` |
| 점검상태 · 알림기록 · 활동알림 | `계정/<이름>/` |
| 길들이기 · 수집 · 하트댓글 · 발행 | 벽이 지킨다 |

**모듈에 남는 값도 훑었다.** 계정을 안 가리는 것은 쿠팡 수익 캐시 하나인데, 쿠팡이 subId 를
비워서 돌려주기 때문에 원래 계정별로 못 가른다(실측, `src/대시보드.mjs:85`).

**`OPENAI_*` 는 아무 코드도 안 쓴다.** 이 제품의 LLM 은 클로드다. 잔재다.
