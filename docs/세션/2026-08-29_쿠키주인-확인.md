# 세션 2026-08-29 — 쿠키 주인 확인

## 한 일

텔레그램에 「스레드 쿠키가 죽은 것 같습니다」가 두 계정에서 반복됐다.
사용자가 「쿠키는 맞게 넣었다. 시스템 원인을 파악해라」고 했다. 실측으로 좁혔다.

### 알아낸 것 (전부 실측)

| 확인 | 결과 |
|---|---|
| 계정 여덟의 쿠키가 살아 있나 | **여덟 다 살아 있다** — 스레드가 주인을 답한다 |
| 토큰 주인 vs 쿠키 주인 | **sample_table 만 어긋난다** — 쿠키 주인이 @sample_minimi |
| 쿠키가 잘려서인가 | **아니다.** 잘 되는 쿠키를 235자로 깎아도 조회수가 온다 |
| 장보는미니미 쿠키 | 주인도 맞고 홈도 로그인되는데 **조회수만** 6번 다 안 온다 |
| 쿠키 없이(로그아웃) | 장보는미니미와 **똑같다** — 좋아요는 오고 조회수만 안 온다 |
| 「어제 N번 안 돌았다」 경보 | **헛경보.** 어제 19:26~19:30 에 시각표를 바꿨는데, 감시기가 오늘 시각표를 어제 기록과 맞춰 봤다 |
| 쟁여둔언니 22:17 실패 | 진짜지만 쿠키와 무관 — 쌓아 둔 8편 중 7편 미디어 중복, 1편은 관문이 막음(400ml) |

### 고친 것 셋

1. **`열쇠저장()` 이 쿠키를 쓰기 전에 주인을 묻는다.** 다르면 던지고 안 쓴다.
   못 읽었을 때는 **안 막는다** — 스레드가 화면을 바꾸면 열쇠 저장이 통째로 죽는다 (`계정벽` 규칙).
   `자동발급` 은 토큰과 쿠키를 **따로** 저장한다 — 허용 화면에서 계정을 바꿔 고르면 둘이 갈리는데,
   한꺼번에 저장하면 쓸 수 있는 토큰까지 버리게 된다
2. **알림이 셋을 갈라 말한다** — 「죽었다 / 딴 계정 것이다 / 살았는데 조회수만 안 온다」.
   셋은 할 일이 서로 다른데 여태 한 마디로 뭉갰다
3. **`도구.계정환경점검.mjs` 가 쿠키의 진짜 주인까지 묻는다.** 돌려서 그 자리에서 하나를 잡았다.
   (`--빠르게` 를 주면 안 묻는다. 상대 경로로 돌리면 import 가 죽던 것도 함께 고쳤다)

## 결정 (왜 그렇게 했나까지)

- **주인을 못 읽었을 때 막지 않는다.** 막으면 스레드가 문서 꼴만 바꿔도 열쇠 저장이 전부 죽는다.
  그건 사고를 막는 게 아니라 프로그램을 죽이는 것이다 (`계정벽.mjs` 47줄의 판단을 그대로 따랐다)
- **점검 도구가 스레드를 두드리게 했다.** 원래 「접속하지 않는다」가 약속이었는데,
  접속을 안 하면 이번 사고를 **원리상 못 잡는다.** 읽기 한 번이고 아무것도 안 바꾼다 — 머리말에 적어 뒀다
- **검사에 `쿠키묻기` 를 갈아 끼울 자리를 냈다.** 안 그러면 `test.토큰받기` 가 진짜 스레드를 두드린다
  ([[검사가-실서버-장부를-쓰면-안-된다]] 와 같은 결)
