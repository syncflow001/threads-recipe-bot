# 세션 2026-08-31

## 한 일

**① 텔레그램이 몇 주 만에 살아났다.** `fetch failed ETIMEDOUT` 인데 `curl` 은 302 를 받던 것을
층마다 재서 원인을 잡았다. Node 의 Happy Eyeballs 문턱이 **250ms** 인데 이 맥의 IPv4 연결이
**251ms** 다. 1ms 차이로 IPv4 를 버리고 **경로가 없는 IPv6**(EHOSTUNREACH)로 넘어가 죽었다.
`src/그물.mjs` 를 불러 쓰면 문턱이 1초로 올라간다. 밖으로 나가는 모듈 **열둘**에 붙였다 —
손으로는 여섯만 찾았는데 **검사가 여섯을 더 찾았다.**

**② 섀도우밴 살피기.** 모니터링 쪽에 카드 하나. 하루 한 번 계정마다 재서 나빠질 때만 알린다.
설명 단추가 `docs/섀도우밴-대응.md` 를 팝업으로 띄운다.

**③ 미디어 찌꺼기 정리.** `계정/` 이 1.4GB 였다. 802MB 를 지우고, 판이 끝날 때마다 저절로 치우게 했다.
겹치는 글은 사진 한 장만 받고 멈추게도 했다.

**④ 공개판 v1.1.0.** 옛 커밋에 실제 계정 아이디가 남아 있어 기록을 갈아엎었다(orphan + force).
README 를 새로 쓰고 `.env.example` 을 만들었다.

**⑤ 수익을 제휴 채널별로.** 목표도 채널마다 따로 세운다. 성적을 아홉 계정 전부 켰다.
길들이기를 한국어 계정도 켤 수 있게 했다. 설정 화면 넷(초록 완료 딱지·터미널·비밀번호 떼기·자동발급 일원화).

**⑥ 레시피 서식을 요리 팩으로 올렸다.** 사용자가 여덟 계정의 실제 발행 글을 나란히 놓고
「왜 통일이 안 되냐」고 물어 드러났다. `sample_salim` 의 말투 파일에 레시피 형식 칸이 통째로
없었고, **팩은 계정 만들 때 한 번 베끼고 판을 돌 때는 안 읽혔다.**
`src/compose.mjs` 의 `서식깔기()` 가 팩을 바탕으로 깔고 계정 말투를 얹게 했다.

**⑦ 첫 줄 훅에 실측 순위를 매겼다.** 사용자 조사(359글) — 「의심 → 반전」 3.7배 ·
「남이 물어봄」 3.5배. 무게를 실측 배수로 두고 `도입고르기` 가 무게만큼 뽑는다.
낮은 것도 9% 는 남겼다 — 매번 같은 훅이면 봇처럼 보인다.
`도입 유형` 은 계정이 못 덮게 했다(`분야가정하는칸`).

## 결정 (왜)

**검수 에이전트를 세 번 붙였고 세 번 다 값을 했다.** 붙일 때마다 내가 못 본 것이 나왔다 —
섀도우밴 신호가 「늘 초록」이라 안 켜지던 것, 아낀 양을 94% 라 적었는데 실은 27% 인 것,
마지막 판 정리가 시간대를 넘기면 통째로 빠지던 것. **매일 도는 길을 건드리면 검수를 붙인다.**

**레시피 서식은 팩이 갖는다 — 「두 곳에 두면 어긋난다」는 옛 판단을 뒤집었다.**
옛 주석은 「persona.json 이 이미 요리 말투니 팩엔 안 둔다」였다. 그 결과 복사본이 열 개가 되어
하나가 망가져도 아무도 못 고쳤다. 지금은 **팩이 바닥을 깔고 계정이 덮는다** — 두 곳이 아니라
한 곳이 바닥이고 한 곳이 덧칠이다. 자세한 것은 [[계정마다-복사본을-두면-아무도-못-고친다]].

**「그날 마지막 판에만 치우기」를 「판마다 치우기」로 바꿨다.** 사용자 제안이었지만 검수에서
셋이 나왔다(시간대 넘김·판 안 뜸·마법 숫자). 판마다 치우면 셋이 한꺼번에 없어지고,
잣대가 **이 판이 시작한 시각**이라 계정 시각표와 무관해진다.
