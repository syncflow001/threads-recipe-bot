# 세션 2026-09-07 — 터진 글에만 링크

## 왜 (2026-09-06 실측)

- 쿠팡 클릭은 우리가 링크 글을 **한 편도 안 올리던** 08-08~08-18 에도 하루 8~20이었고,
  08-19 부터 하루 6~25편을 올렸는데 **안 늘었다.** 우리 글 한 편당 클릭은 0에 가깝다
- 예외는 08-28 — `sample.unni` 글이 4만 조회로 터진 날 234클릭. **클릭은 링크 수가 아니라 조회수가 만든다**
- 우리는 하루 4.3~5.0편 · 광고 45~91%. 조사(`docs/조사-광고비율.md`)가 권한 값은 하루 2편 · 광고 0~1편
- 그러니 모든 글에 링크를 다는 것은 19편의 도달을 깎아 0을 얻는 장사다

**사용자가 정했다** — 문턱은 **올린 지 30시간 이내 · 조회수 1만 이상.** 그 글에만 링크를 단다.

## 한 일 (계획대로 다 했다)

1. 발행(`run.mjs`)은 **늘 깨끗하게** 올린다 — 링크 없음 · 광고 표시 없음 · 재료 이름 다 공개.
   핵심재료는 그대로 뽑아 `재구성.json` 에 남긴다 (나중에 링크를 만들 재료다)
2. 조회수 알리미(30분마다 도는 것)가 이미 「최근 글 중 1만 넘은 것」을 고른다.
   창을 2일 → **30시간**으로 바꾸고, 넘은 글에 **링크 답글을 단다**
3. 링크 답글 = `{핵심재료} 어디서 샀냐고 많이 물어보셔서 👇` + 쿠팡 링크 + 대가성 문구 + 「광고」 주제 태그.
   본글에 다는 답글이다 (레시피 답글은 이미 달려 있다)
4. 한 글에 한 번만 단다 — `재구성.json` 의 `발행.늦은링크` 에 적고, 달기 전에 스레드에서도 링크가 있는지 본다
5. 「제휴 링크 넣기」 스위치는 그대로 쓴다 — 켜진 계정만 뒤늦게 단다. 뜻만 바뀐다
6. 화면 글귀를 바꾼다 (「레시피 답글에 쿠팡 링크를 넣어요」 → 「1만 조회를 넘긴 글에만」)

## 결정 (왜 그렇게 했나까지)

- **링크는 발행 때 만들지 않고 달 때 만든다.** 95%의 글은 링크가 안 붙는데 글마다 쿠팡 API 를
  두드리면 헛일이다. 핵심재료만 남겨 두면 그때 만들 수 있다
- **스위치를 새로 만들지 않는다.** 「제휴 링크 넣기」가 켜진 계정 = 터지면 다는 계정.
  비개발자에게 스위치가 둘이면 헷갈린다. 옛 방식(발행 때 넣기)은 git 에 남아 있다
- **알림 창도 30시간으로 같이 간다.** 「지금 터지는 글」의 뜻은 하나여야 한다 — 알림은 2일,
  링크는 30시간이면 사람이 두 숫자를 기억해야 한다
- **한 번 알린 기록(알림기록.jsonl)과 링크 단 기록(재구성.json)은 따로 둔다.**
  알림은 됐는데 링크 달기가 브라우저에서 죽으면 다음 30분에 다시 해야 한다.
  알림 기록으로 막으면 그 글은 영영 안 달린다

## 실제로 돌면 이렇게 보인다

`logs/조회수알리미.out` 에 30분마다 — 넘긴 글이 있으면 `  계정 code → ✅ 달았다` 또는 `건너뜀 — 까닭`.
텔레그램에 「🔗 [계정] 터진 글에 링크를 달았습니다」 + 상품 + 주소. 「광고」 주제를 못 달았으면 ⚠️ 가 붙는다.
`계정/<계정>/media/쓴것/<code>/재구성.json` 의 `발행.늦은링크` 에 단때·조회수·상품·주제결과가 남는다.

## 이어서 — 달았다·못 달았다 알림과 스위치 (같은 날, 사용자가 시켰다)

- **달면** 텔레그램 「🔗 [계정] 터진 글에 링크를 달았습니다」 + 상품 + 주소. 「광고」 태그를 못 붙였으면 ⚠️ 를 붙인다
- **못 달면** 「❌ [계정] 터진 글에 링크를 못 달았습니다」 + 조회수 + 까닭. 브라우저가 죽었든, 로켓배송 상품이 없든.
  「이미 달려 있다」는 실패로 안 센다 (`실패인가`)
- **스위치** — 모니터링 화면에 「링크 달기 알림」 카드. 알림만 끈다, 달기는 계속한다.
  값은 뿌리 `알림설정.json` (계정이 아니라 이 맥 전체의 규칙 — 발행간격.json 과 같은 자리).
  파일이 없거나 깨지면 **켜짐** — 조용히 꺼지는 쪽이 더 위험하다
- 길 — `GET/POST /late-link-alert` (`dashboard/app/api/late-link-alert/route.ts`) ·
  카드 `dashboard/components/쪽/monitor/늦은링크알림.tsx` · 몸통 `src/늦은링크.mjs` 의 `알림설정읽기/쓰기`
- 고친 김에 — 알리미 결과 파일에 `설정.며칠`(이제 없는 이름)이 적히던 것을 `시간`으로 바로잡았다
- 검사 1묶음 더 (`test.늦은링크.mjs` ⑨) — 기본값·깨진 파일·실패의 뜻·알리미가 스위치를 읽는지

## 이어서 — 「광고」 주제를 못 달아도 답글은 나간다 (같은 날, 사용자가 정했다)

「광고」 표시가 없어도 답글 안에 **대가성 문구**가 있으면 표기는 갖춰진 것이다.
`브라우저로답글달기` 는 원래 주제 실패를 던지지 않고 게시했다 — 이번에 둘을 더했다.

- **엉뚱한 주제가 반쯤 들어갔으면 비우고 나간다.** 「광고대행사」가 칸에 남은 채 올리면 그 주제로 나간다.
  `fill('')`, 안 되면 전체 선택 → 지우기. 비우기도 실패하면 그냥 올린다 — 글이 먼저다
- 텔레그램 문구를 낮췄다 — 「손으로 달아 주세요」가 아니라 「대가성 문구는 들어 있어 표기는 갖춰져 있습니다」
