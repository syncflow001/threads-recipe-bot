## 믿었던 것

코드 주석에 「`node --env-file` 은 **이미 환경에 있는 변수를 덮어쓰지 않는다**(실측)」이라
적혀 있었다. 그래서 `--env-file=.env.local --env-file=계정/x/열쇠.env` 순서면
**앞의 공용 파일이 이긴다**고 읽었다.

## 해본 것

계정 열쇠 파일 하나(`sample.unni`)에만 공용 열쇠(쿠팡·OPENAI) 사본이 남아 있는 것을
발견하고, 위험한지 재보려고 직접 잼.

```
a.env: K=로컬것    b.env: K=계정것
node --env-file=a.env --env-file=b.env  →  K = 계정것
```

## 나온 것

**뒤에 오는 것이 이긴다.** 주석의 「덮어쓰지 않는다」는 **부모 프로세스 환경**에 대한
이야기였다 — `--env-file` 끼리는 다르다. 두 이야기가 한 주석에 섞여 있었다.

즉 계정 파일에 공용 열쇠 사본이 있으면 **그 계정만 딴 쿠팡 키로 링크를 만든다.**
지문으로 대조하니 값 셋이 **우연히 같아서** 안 터지고 있었다.

## 지금 결론

**계정 열쇠 파일에는 그 계정 것만 둔다.** 공용 열쇠(쿠팡·텔레그램·블롭·스레드 앱)는
`.env.local` 한 곳에만 산다. 사본을 두면 조용히 덮는다.

검사로 못 박았다 — 계정 열쇠 파일에 공용 열쇠 이름이 하나라도 있으면 빨간불이다.

**그리고 주석에 「실측」이라 적혀 있어도 다시 재본다.** 그 주석은 틀리지 않았다.
다른 것을 말하고 있었을 뿐이고, 그걸 가르는 것은 읽는 사람 몫이었다.
