## 믿었던 것

첫 계정을 `example.cook` 로 옮기는 계획을 「옮기는 것 목록」 표로 만들었다.
표는 **파일 이름**(`.env.local`→`.env.example.cook` 따위)과 **장부 키**(`""`→`"example.cook"`)로만 이루어져 있었다.
표대로 다 옮겼으니 끝났다고 믿었다.

## 해본 것

검사 스물둘, 검토 네 판(과제 검토 · 고침 재검토 · 전체 검토 · 고침 재검토), 실행 뒤 확인 다섯 —
**전부 통과했다.** 그런데 그 뒤 사용자가 「이제 다 끝난 건가요」라고 물어 `CHECKLIST.md` 를 훑다가,
`최근글()` 관련 낡은 메모 한 줄이 눈에 걸려 실제로 재 봤다.

## 나온 것

```
example.cook       → 최근글 0 편      (실제로는 53편이 있었다)
sample.unni      → 최근글 58 편     (정상)
```

글 하나하나가 `media/<계정>/쓴것/<code>/재구성.json` 인데, 발행된 글에는 `run.mjs:390` 이 쓴
`"발행": { "계정": "", ... }` 칸이 있다. **옛 이름(빈 문자열)이 값으로 박혀 있었다.**

그 값을 읽는 곳이 셋이고 전부 계정 이름과 정확히 견준다 —
`src/대시보드.mjs:512`(최근글) · `src/성적.mjs:60`(조회수·좋아요) · `src/도달.mjs:51`(확산).
`'' !== 'example.cook'` 라 **42편이 전부 걸러졌다.**

화면만의 문제가 아니었다 — **성적과 도달 측정이 통째로 멈춰 있었다.**
발행은 정상으로 됐다. 재는 쪽만 죽어 조용했다. 그래서 아무 경보도 안 울렸다.

고친 뒤: `최근글 42편`, 성적·도달이 잴 글도 42편. (나머지 11편은 발행 안 된 초안이라 그대로 둔다 —
셋 다 `if (!글?.발행?.본문번호) continue` 로 먼저 걸러진다.)

도구에 이관을 넣었고(`옮기기` 는 옮기고 `되돌리기` 는 되돌린다), 이미 옮겨진 데이터를 위해
`--글계정고치기 <이름>` 갈래를 뒀다. 커밋 `8b1ff83`.

## 지금 결론

**이름을 바꿀 때는 「그 이름이 파일 이름인 곳」과 「그 이름이 값으로 적힌 곳」을 따로 세어라.**
후자는 `grep` 으로 찾는다 — 이번 경우 `grep -rn "발행?\.계정\|발행\.계정" src` 세 줄이 전부였다.
**그 값을 읽어 견주는 코드를 찾는 것**이 가장 빠른 길이다(쓰는 곳 하나, 읽는 곳 셋).

그리고 **검사와 검토는 자기가 아는 것만 본다.** 이번 검사 스물둘·검토 네 판은 전부 파일과 장부만 봤다 —
계획 표에 없던 것은 아무도 안 봤다. 계획 표가 곧 검토의 시야다([[계획표의-공용-표시를-믿지-말고-읽는-코드를-따라가라]] 와 같은 뿌리다).
**옮긴 뒤에는 표를 덮고, 그 계정으로 화면을 한 번 열어 숫자를 눈으로 봐라** —
「최근글 0편」은 표 대조로는 영원히 안 나온다.

## 아직 모르는 것

`재구성.json` 안에 계정 이름이 값으로 적힌 다른 칸이 더 있는지는 `발행.계정` 하나만 확인했다.
다른 장부(`글성적장부.json` 따위) 안쪽 값에도 옛 이름이 박혀 있는지는 아직 안 봤다 — 키만 봤다.
