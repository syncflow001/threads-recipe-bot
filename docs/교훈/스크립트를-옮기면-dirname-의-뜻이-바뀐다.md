## 믿었던 것

뿌리에 흩어진 파일을 `도구/`·`검사/` 로 정리했다. **파일 안의 경로만 고치면 된다**고 봤다.
`import` 205곳을 고쳤고, 참조하는 문서와 설정도 훑었다. `./검사.sh` 는 26개 전부 초록이었다.

## 해본 것

옮긴 것을 하나씩 **직접 눌러 봤다.** `bash 도구/세션부팅.sh` 를 돌렸다.

## 나온 것

**44줄이 나와야 하는데 1줄만 나왔다.** 오류는 없었다. 종료코드도 0 이었다.

```bash
cd "$(dirname "$0")" || exit 0    # 뿌리에 있을 땐 저장소 뿌리
                                  # 도구/ 로 옮기니 도구/ 가 됐다
last=$(ls -t docs/세션/[0-9]*.md ...)   # 도구/docs/세션/ 을 찾는다 → 없다
```

이 훅은 **새 세션이 지난 기록과 교훈을 물려받는 유일한 길**이다. 그것이 죽었는데
검사는 초록이었고, 사람이 눌러 보기 전까지 아무도 몰랐다.

같은 날 하나 더 나왔다 — `src/업데이트.mjs` 는 **`공개판올리기.mjs` 가 있느냐**로
「여기가 제작자 저장소인가」를 판별한다. 그 파일을 옮겨 못 찾게 되면
**자동 업데이트가 작업 중인 저장소를 덮는다.** 이것도 검사가 초록이었다 —
검사도 옛 이름으로 임시 파일을 만들고 있어서 코드와 검사가 나란히 틀렸다.

## 지금 결론

**파일을 옮길 때 세 가지를 함께 본다.**

1. **`import('./x')` 는 파일 자리 기준, `readFile('./x')` 는 실행 위치 기준.** 같은 글자, 다른 뜻이다.
   `from`·`import(` 낱말이 앞에 붙은 것만 고친다
2. **셸의 `dirname "$0"` · `dirname "${BASH_SOURCE[0]}"`** — 한 겹 들어가면 `/..` 를 붙인다
3. **파일의 존재 자체를 표시로 쓰는 코드**가 있는지 찾는다. 그런 코드는 옮긴 것을 못 찾으면
   조건이 조용히 뒤집힌다

그리고 **검사를 옮길 때는 코드와 검사가 나란히 틀리지 않았는지 본다.** 둘 다 옛 자리를 쓰면
초록이 나온다. 이번에 세 번 겪었다 (팔로우장부·업데이트 방어벽·세션부팅).

`검사/test.도구.mjs` 를 새로 만들어 「돌긴 도는가」만 재게 했다. 무엇을 하는지는 안 본다 —
**그것만으로 이 종류의 사고가 다 걸린다.** 일부러 `/..` 를 떼어 빨간불이 나오는 것까지 확인했다.

## 아직 모르는 것

`도구/화면다시짓기.sh` 는 빌드를 시작하는 스크립트라 끝까지 돌려 보지 않았다.
경로를 뿌리로 잡는 것과 첫 줄이 나오는 것만 봤다.
