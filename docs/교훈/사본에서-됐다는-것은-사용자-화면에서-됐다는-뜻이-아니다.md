## 믿었던 것

「검사 통과 · 빌드 통과 · 브라우저로 직접 눌러 확인」까지 했으니 **끝났다**고 봤다.
`CLAUDE.md` §2-5 가 시키는 「사람이 눌러보는 단계」까지 지켰다고 여겼다.

## 해본 것

작업 사본 `~/orca/workspaces/coupas-auto/대시보드-디자인` 에서 대시보드 넷을 고쳤다
(색 되돌리기 · 계정 목록 폭 · 자동 배정 20분 · 제휴 링크 스위치).
확인은 그 사본을 **7801번**에 따로 띄워서 했다. 그리고 「다 했습니다」라고 보고했다.

사용자가 자기 화면을 봤다 — `127.0.0.1:7788/overview`. 없었다. 「없는데? 주소가 다른가?」

## 나온 것

주소는 맞았다. 그 화면을 띄우는 프로세스의 작업 폴더가 달랐다.

```
lsof -ti:7788                      → PID
lsof -p <PID> -a -d cwd            → /Users/사용자/projects/coupas-auto
```

내가 고친 것은 **사본 갈래에 커밋만 돼 있었다.** 원본에는 한 글자도 안 갔다.
합치고 다시 지어 켜니 그제야 화면에 나왔다.

같은 뿌리의 실패가 **열흘 안에 두 번째**다. 2026-08-28 지식축적 세션에서도
「낡은 갈래에서 검토하고 main 과 안 맞춰 본 것이 원인」이라고 적었다
(`docs/세션/2026-08-28_지식축적-장치.md` 알게 된 것 4번). 그때는 검토였고 이번은 배포다.

## 지금 결론

**작업 사본에서 일할 때는 「됐다」가 아니라 「사본에서 됐다」고 말한다.**
사용자가 결과를 눈으로 볼 일이면, 보고하기 **전에** 그 화면을 띄우는 폴더를 확인한다 —
`lsof -ti:<포트>` 로 PID 를 잡고 `lsof -p <PID> -a -d cwd` 로 작업 폴더를 본다.
사본과 다르면 합칠지 사용자에게 먼저 묻는다. 원본에 다른 작업이 놓여 있을 수 있다
(이번에도 커밋 안 된 말투 파일 다섯이 있었다 — 겹치는 파일이 없어 무사했다).

[[검사-초록이어도-단추는-사람이-누른다]] 의 형제 카드다. 그 카드는 「자동 검사 ≠ 사람이 누름」이고,
이 카드는 「내가 누른 화면 ≠ 사용자의 화면」이다.

## 아직 모르는 것

이 저장소에서 앞으로도 작업 사본을 쓸지, 아니면 원본에서 갈래만 갈아 쓸지는 안 정했다.
사본을 계속 쓴다면 `dashboard/node_modules` 를 매번 새로 깔아야 한다는 비용도 함께 온다
(이번에 `test.대시보드.mjs` 가 그것 때문에 죽었다).
