## 믿었던 것

답글 한도가 490자니 레시피도 그쯤 쓰면 된다고 여겼다. 사용자가 「글자 제한 480자로 늘려」라
했을 때 **팩의 레시피 길이 지시**를 480으로 올렸다.

## 해본 것

실제로 붙여 보고 길이를 쟀다.

## 나온 것

**레시피 480자 → 답글 621자.** 한도를 130자 넘겨 둘로 쪼개졌다.

레시피 말고 **덧붙는 것이 약 128자** 있었다 —
링크 두 번(74) + 대가성문구(32) + 한 줄 소개(17) + 빈 줄.
그것을 세지 않고 「480자」만 보았다.

바로잡고 경계를 다시 쟀는데 **여기서 또 틀렸다.** 시험 레시피를 **줄 단위**로 늘려 재니
상한이 340자로 나왔다. **글자 단위**로 다시 재니 **362자**였다 —
재료 한 줄이 통째로 들어가느라 12자가 작게 잡힌 것이다.

| | 상한 | 그때 답글 |
|---|---|---|
| 줄 단위로 쟀을 때 | 340자 | 471자 (19자를 놀렸다) |
| 글자 단위로 쟀을 때 | **362자** | **490자** |

## 지금 결론

**「몇 자까지」를 정할 때 두 가지를 먼저 한다.**

1. **덧붙는 것을 세어 뺀다.** 사람이 쓰는 것 말고 코드가 붙이는 것 — 링크·표기·문구·빈 줄
2. **재는 눈금을 본다.** 줄·문단 단위로 늘리며 재면 마지막 한 덩어리가 통째로 걸려
   실제보다 작게 잡힌다. **1자씩 늘려 가며 경계를 찾는다**

그리고 **한도는 지시가 아니라 결과로 확인한다** — 팩에 「360자」라 적는 것과
실제 답글이 490자 안에 들어가는 것은 다른 일이다. 붙여 보고 세어야 안다.

## 아직 모르는 것

덧붙는 128자는 **링크 주소 길이에 따라 달라진다.** 쿠팡 단축 주소는 37자인데
더 긴 주소가 오면 경계가 밀린다. 지금은 여유 두 자뿐이라 아슬아슬하다 —
링크가 길어지는 날 답글이 조용히 쪼개질 수 있다.

## 이어서 (2026-09-02) — 덧붙는 양이 **고정이 아니었다**

같은 날 셋째로 틀렸다. 「덧붙는 것 128자」를 **상수처럼 다뤘는데 아니었다.**

- 링크 줄에서 상품 이름을 빼자 덧붙는 양이 128 → **114자**로 줄었다
- 그런데 **가림막(한줄소개)은 LLM 이 짓는다.** 9자면 레시피 370자까지, 40자면 **341자까지**다

**덧붙는 것 가운데 사람이 안 정하는 것이 있으면, 경계는 「가장 나쁠 때」로 잡는다.**
평균으로 잡으면 절반이 쪼개진다. 340자로 내렸다 — 짧은 가림막에선 30자쯤 남지만,
남기는 쪽이 쪼개지는 쪽(0.62배)보다 싸다.

검사도 바꿨다. 숫자를 검사 파일에 또 적으면 팩과 어긋나므로 **팩이 시키는 값을 받아서** 본다.
그리고 **가장 긴 가림막**으로 실제로 재어 한 조각인지 확인한다.
