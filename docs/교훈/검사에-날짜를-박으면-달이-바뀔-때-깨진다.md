## 믿었던 것

`test.안전장치.mjs` 가 첫판 날짜 찾기를 재면서 `b-2026-07.log`·`2026-08-19` 처럼
**날짜를 박아** 두었다. 고정값이라 흔들릴 일이 없다고 봤다.

## 해본 것

2026-08-31 밤 11시에 검사를 돌려 초록을 보고 커밋했다. 자정을 넘겨 9월 1일 0시 7분에
다시 돌리니 **빨간불**이었다.

## 나온 것

`첫판때찾기`(`src/감시모음.mjs`)는 **「이번 달」과 「지난달」 로그만** 읽는다.
9월 1일이 되자 이번 달은 `2026-09`, 지난달은 `2026-08` 이 됐고, 검사가 만든 `2026-07` 로그는
**읽는 범위 밖**으로 밀려났다.

코드는 아무것도 안 바뀌었다. **달력이 바뀌었을 뿐이다.**

내 변경 탓인 줄 알고 방금 커밋을 의심했다 — 아니었다.
「검사가 빨간불이면 내가 방금 한 것 탓」이라는 기본 가정이 여기서는 틀렸다.

## 지금 결론

**「이번 달·지난달」처럼 오늘을 기준으로 도는 코드의 검사에는 날짜를 박지 않는다.**
오늘에서 파일 이름과 기대값을 **함께** 만든다.

```js
const 달이름 = (d) => `${d.getFullYear()}-${두자리(d.getMonth() + 1)}`
const 지난달 = new Date(오늘.getFullYear(), 오늘.getMonth() - 1, 1)
// 파일 이름도 기대값도 이 둘에서 뽑는다
```

미뤄 두었던 「`test.안전장치.mjs` 의 단정이 실제 상태에 흔들린다」가 이것이었다.
같은 병을 가진 검사가 또 있으면 같은 날 함께 깨진다.

**빨간불을 보면 먼저 「무엇이 바뀌었나」를 묻는다** — 내 코드만이 답이 아니다.
날짜·시각·바깥 서비스·맥 상태가 다 바뀔 수 있다.

## 아직 모르는 것

`첫판때찾기` 가 두 달만 보는 것이 맞는지는 안 따졌다. 석 달 넘게 돌아온 계정의
「첫판 날짜」는 실제 첫판이 아니라 두 달 전 어느 날이 된다. 지금 쓰임(「아직 안 함」 가리기)에는
지장이 없어 보이지만 확인은 안 했다.
