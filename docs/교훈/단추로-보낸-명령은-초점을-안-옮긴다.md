## 믿었던 것
대시보드 터미널에서 도는 명령을 그만두려면 `Ctrl+C` 를 누르면 된다고 안내했다.
터미널은 진짜 pty 라 `\x03` 이 닿으면 SIGINT 가 간다 — 그러니 안내대로 하면 멈춘다고 봤다.
사용자가 「Ctrl+C 가 안 먹는다」고 했다.

## 해본 것
셋으로 갈라 쟀다 (2026-09-08). 터미널에서 `sleep 300` 을 돌려 놓고 —
① API 로 `\x03` 을 직접 보내기 · ② 터미널 **밖**(단추)에 초점을 두고 Ctrl+C · ③ 터미널 **안**을 누른 뒤 Ctrl+C.

## 나온 것
| 어떻게 | 결과 |
|---|---|
| ① `\x03` 을 API 로 보냄 | 멈춤 ✓ |
| ② 터미널 밖에서 Ctrl+C | **안 멈춤** |
| ③ 터미널 안을 누른 뒤 Ctrl+C | 멈춤 ✓ |

뒷단은 처음부터 멀쩡했다. 문제는 **초점**이었다 — 「자동발급」 단추로 명령을 보낸 사람은
초점이 그 단추에 남아 있어서, 키를 눌러도 xterm 이 아예 못 받는다.
안내문은 **초점이 터미널에 있는 사람만** 쓸 수 있는 말이었다.

## 지금 결론
**키보드로 하라고 안내할 때는, 그 키가 닿을 자리에 초점이 있는지 함께 본다.**
단추로 무엇을 시작했으면 멈추는 것도 단추여야 한다 — 터미널 창 머리에 「멈추기」를 달았고
(`dashboard/components/쪽/admin/터미널창.tsx`), 초점과 상관없이 `\x03` 을 보낸다.
안내 문구도 「멈추기를 누르세요」로 바꿨다.
같은 결의 카드 — [[검사-초록이어도-단추는-사람이-누른다]].

## 아직 모르는 것
창이 여럿일 때 「멈추기」는 그 창만 멈춘다. 명령이 어느 창에서 도는지 헷갈리는 경우는 안 재 봤다.
문서점검은 **색인에만 있고 카드가 없는 줄**은 안 잡는다 — 이 카드를 쓰다 실제로 겪었다.
