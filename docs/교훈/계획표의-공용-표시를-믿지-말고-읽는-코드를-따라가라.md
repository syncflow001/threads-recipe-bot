## 믿었던 것

첫 계정 이름 붙이기 계획의 「옮기는 것 목록」 표 마지막 줄에 `미디어지문.json` `올린요리.json` `길들이기.sh` 를
**「그대로 — 전체 공용」** 으로 적었다. 도구도 그대로 따라 만들었고, task 검토와 고침 재검토 두 판이
「표 11줄 전부 대응 있음, Spec ✅」로 통과시켰다. **표를 기준으로 대조하면 표의 오답은 절대 안 걸린다.**

## 해본 것

전체 검토(가장 센 모델)에게 「계획 자체에 문제가 있으면 그렇다고 말해라」를 넣어 붙였고,
검토가 걸어 준 근거를 컨트롤러가 직접 다시 쟀다.

## 나온 것

`미디어지문.json` 은 **계정별이다.** 근거 넷.

- `src/미디어지문.mjs:35` — `export const 장부길 = (뿌리) => \`${뿌리}/미디어지문.json\``
- `run.mjs:54` — `const 뿌리 = 미디어뿌리(프로필)` (그 뿌리로 `이미올린미디어`·`미디어적기` 를 부른다)
- `src/계정.mjs:153` — `export const 미디어뿌리 = (계정) => (계정 ? join('media', 계정) : 'media')`
- 실제 파일 — 이름 있는 계정 다섯이 저마다 `media/<이름>/미디어지문.json` 을 갖고 있다.
  첫 계정 것은 `media/미디어지문.json`, 38,329바이트, 그날 오후에도 갱신되고 있었다.

안 옮겼으면 옮긴 직후 지문 장부가 **빈 채로 시작해 이미 올린 사진을 다시 올린다.**
사용자가 확정한 중복 판정 기준(「미디어로만 가린다」)에서 이게 유일한 막이고,
`--되돌리기` 로도 **이미 올라간 글은 못 지운다.**

계획을 오답으로 끌고 간 것은 `run.mjs` 의 낡은 주석이었다 —
「미디어(media/)는 일부러 계정끼리 함께 쓴다」. `src/계정.mjs:153` 이 이미 계정별로 갈라 놓은 뒤였는데
주석만 옛말로 남아 있었다. 커밋 2579624 에서 주석과 계획 표를 함께 고쳤다.

같은 줄의 나머지 둘은 검증 결과 **정말 공용이 맞았다** — `media/막힌것` 은 `src/관문.mjs:5` 의
`보류함 = join(뿌리, 'media', '막힌것')` 에서 뿌리가 저장소 뿌리이고, `올린요리.json` 은 엔진 어디서도 안 읽는
죽은 파일이다(참조는 `test.공개판.mjs:50` 의 제외 목록뿐). **셋 중 하나만 틀렸다** — 그래서 더 안 보인다.

## 지금 결론

**파일을 「안 옮긴다」고 정할 때는, 그 파일을 읽는 코드가 계정별 뿌리를 쓰는지 `장부길`·`뿌리` 인자를 타고
직접 따라가 본다.** 계획 표도 주석도 근거가 아니다 — 근거는 그 파일 경로를 만드는 줄 하나다.
그리고 **검토자에게 「계획 자체가 틀렸으면 말해라」를 반드시 넣는다.** 표를 기준으로만 대조하는 검토는
표의 오답을 구조적으로 못 잡는다 — 이번에 두 판이 연달아 통과시켰다.

## 아직 모르는 것

`media/` 아래 공용/계정별이 섞인 다른 파일이 더 있는지는 이번에 넷(`미디어지문` `올린요리` `막힌것` `프로필.jpg`)만 봤다.
새 계정을 만들 때 `미디어지문.json` 이 자동으로 생기는지도 안 봤다 — 없으면 빈 장부로 시작하는 게 정상 동작인 듯하다.
