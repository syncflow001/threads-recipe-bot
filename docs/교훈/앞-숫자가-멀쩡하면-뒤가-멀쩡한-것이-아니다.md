## 믿었던 것

말투 추천이 「걷은 글 40 · 후보 30 · 팔로워 300명 넘는 것 20 · 요리 계정 12 · **확산을 잰 것 0**」
으로 끝났다. 앞 넷이 멀쩡하니 마지막 단계에서 무언가 새로 막힌 것이라고 봤다 —
문서를 90장 몰아 받아 스레드가 조인 것(rate limit)이라고 짐작했다.

## 해본 것

`example.cook` 쿠키로 그대로 한 판 돌리며 요청마다 결과를 찍었다. 그다음 **같은 글 하나**를
계정 열둘의 쿠키로 돌려 가며 받아 조회수 칸이 실리는지 셌다.

## 나온 것

- 조임이 아니었다. 한 판 48건 중 **47건이 숫자를 받았고** 추천도 6곳이 정상으로 나왔다
- 같은 글·같은 순간에 열 계정은 조회수를 받고 **`sample_yori` 만 못 받았다.**
  문서 크기가 590~620KB 대 750~843KB 이고, `impression_count` 칸이 **통째로 없다**
- **쿠키 없이 받으면 증상이 똑같다.** 검색과 프로필(팔로워)은 로그아웃 상태에서도 나오고,
  조회수만 로그인 문서에 실린다 — 그래서 **앞 넷이 멀쩡해 보이고 마지막만 0** 이 됐다
- 실패는 `상세채우기` 가 `catch { p.조회수 = null }` 로 통째로 삼키고 있었다 (`src/threads.mjs`)

## 지금 결론

**한 칸만 0이면 「그 칸에만 필요한 조건」을 먼저 찾는다.** 앞 칸이 멀쩡한 것은
그 조건 없이도 채워지기 때문일 수 있다 — 앞이 멀쩡하다는 것이 뒤의 알리바이가 아니다.

반영 — `퍼지는계정찾기` 가 검색 직후 문서 **세 장**으로 조회수가 읽히는지 먼저 재고,
못 읽으면 쿠키가 없는지·안 먹는지를 갈라 말하고 멈춘다. 못 읽으면 **읽기에 한해**
다른 계정 로그인을 빌리고 누구 것인지 밝힌다 (커밋 `958cade`·`5f4617a`).
