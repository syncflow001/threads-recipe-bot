## 믿었던 것

공개 저장소에 올릴 때 말투 파일을 **내보내면서 개인적인 칸을 지웠다.** 「내 글 예시」를
비우면 안전하다고 봤다. 코드 주석도 그 파일을 「빈 서식」이라 불렀다.

## 해본 것

파일 이름을 `persona.json` → `말투바탕.json` 으로 바꾸다가 공개판 도구가 안 따라간 것을
검증 에이전트가 잡았다. 그 김에 **실제로 무엇이 나가는지** 칸마다 재봤다.

## 나온 것

「빈 서식」이 전혀 비어 있지 않았다.

| 칸 | 들어 있던 것 |
|---|---|
| `_설명` | **계정 아이디(@example.cook)** |
| 정체성 | 42자 |
| 말투 | 190자 |
| 자주 쓰는 표현 | 6개 |

지우는 칸을 넷으로 늘렸다. 그래도 **팔로워 애칭 「스치니」가 「쓰지 말 것」 칸에 숨어**
그대로 나갔다. 「출처를 밝히지 말 것 (단, '어떤 스치니가 올린 거…'는 예외)」 같은 문장 속이었다.

## 지금 결론

**사람이 자유롭게 쓰는 글에서 개인적인 것만 골라 지우는 방식은 반드시 샌다.**
지울 칸을 늘려도 다음 칸에 또 숨는다 — 빼놓는 목록(denylist)의 숙명이다.

`.env.example` 과 같은 방식으로 간다. **사용자 파일은 아예 안 내보내고, 고정된 서식 파일을
따로 둔다.** 지워내는 함수는 없앴다 — 남겨 두면 또 쓰게 된다.

그 김에 더 큰 것도 막았다 — **`계정/` 폴더는 통째로 안 나간다.** `.gitignore` 가 빼 주고
있었지만 **비밀을 그것 하나에 기댈 수 없다.** `열쇠.env` 는 `.env` 로 **시작**하지 않아
열쇠 거르는 규칙에도 안 걸렸다.

## 아직 모르는 것

- 고정 서식이 낡을 수 있다. 사용자 파일에 칸이 늘면 서식은 그대로다 — 지금은 사람이 맞춰야 한다
