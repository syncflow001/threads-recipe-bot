## 믿었던 것
조사 결과를 요리팩에 반영했으니 열한 계정이 그대로 쓴다고 믿었다. 검사도 초록이었고
팩 파일을 열면 새 값이 분명히 있었다.

## 해본 것
사용자가 「전수 조사해서 보고하라」고 해서, 믿는 대신 **실제 프롬프트를 뽑아 봤다.**

```
node -e "…프롬프트만들기(원글, 페르소나, 묶음).system…"
```

## 나온 것
`example.cook` 에 나가던 프롬프트에 이렇게 적혀 있었다.

```
[길이] … 레시피 재료와 순서를 합쳐 25줄 이내          ← 옛 값 (팩은 17줄·340자)
[레시피 형식] … 단계마다 요령을 한 줄 덧붙인다.
              마지막은 '~가 진짜 포인트야' 같은 핵심 한 줄로 맺는다.   ← 지운 그것
```

**계정의 `persona.json` 이 팩을 덮고 있었다.** 한국어 요리 계정 일곱 중 **여섯**이
아직 「25줄」을 시키고 있었다. 앞 세션에 고친 것이 사실상 한 계정에만 먹혔다.
까닭은 `서식깔기` 의 「분야가 정하는 칸」에 **「도입 유형」 하나만** 있었기 때문이다.

그 뒤에 같은 함정을 세 번 더 찾았다.
- **자유 서술 칸**은 이름 있는 칸을 갈라도 안 막힌다 — `말투` 안에 「본문 딱 3줄」이 베껴져 있어
  팩의 「본문 4~5줄」과 같은 프롬프트에 나란히 나갔다
- **댓글·답글은 딴 길로 간다** — `활동말투.mjs` 가 `서식깔기` 를 안 거쳐, 뼈대를 팩으로 옮긴 뒤
  「쓰지 말 것」이 열한 계정 전부에서 사라졌다. 안 터져서 아무도 몰랐다
- **한 언어만 고치면 나머지가 뒤처진다** — 한국어팩만 고쳐 일본어·영어가 25행으로 남아 있었다

## 지금 결론
**「고쳤다」와 「그 말이 LLM 에 닿는다」는 다른 사건이다.** 팩·설정을 고쳤으면
**실제 프롬프트를 뽑아 눈으로 본다.** 검사 초록도, 파일을 열어 본 것도 증거가 아니다.
덮을 수 있는 자리가 넷이다 — ①이름 있는 칸 ②자유 서술 칸 ③딴 길로 가는 부품 ④다른 언어팩.

반영: `서식깔기` 가 팩 칸을 못 덮게 했고(`3156965`), 말투 칸에 구조 낱말이 들어오면
빨간불이 뜨며(`5114dde`), 세 언어팩이 같은 것을 시키는지 **뜻으로 견주는** 검사를 붙였다(`f5d3c19`).

## 아직 모르는 것
- 활동말투 말고도 `서식깔기` 를 안 거치는 길이 더 있는지 — 오늘은 grep 으로만 훑었다
- 대시보드 화면이 보여 주는 값과 실제 프롬프트가 같은지 — 화면 쪽은 안 대조했다
