## 믿었던 것

보고서 화면의 번호 목록을 두 칸짜리 배치로 짰다. **왼쪽 칸에 번호, 오른쪽 칸에 내용**이라
생각했다.

```html
<li><b>제목</b>설명글이 여기 이어진다</li>
```

칸을 나누는 규칙에 `minmax(0,1fr)` 까지 넣어 「오른쪽 칸은 좁아져도 안 무너진다」고 여겼다.

## 해본 것

사용자가 화면을 찍어 보냈다. 설명글이 **한 글자씩 세로로** 서 있었다.
브라우저에서 글자 뭉치의 실제 크기를 쟀다.

## 나온 것

칸을 나눈 배치에서는 **태그로 안 감싼 맨 글도 한 칸을 차지한다.** 자식이 셋이 된다 —
번호(::before) · `<b>` · **맨 글**. 칸은 둘뿐이라 맨 글이 다음 줄 **왼쪽 칸**,
곧 번호 자리(25px)로 밀려났다.

되살려 재 보니 **여섯 곳이 폭 25px · 높이 2,976px** 였다. 고친 뒤에는 0곳이다.

**내 첫 검사가 이것을 못 잡았다.** `querySelectorAll` 로 **요소만** 쟀기 때문이다.
맨 글은 요소가 아니라 잡히지 않았고, 나는 「재현이 안 된다」고 사용자에게 말했다.
`document.createRange().selectNodeContents(텍스트노드)` 로 재고 나서야 보였다.

## 지금 결론

**칸을 나눈 배치 안에는 맨 글을 두지 않는다.** 전부 태그로 감싸거나, 애초에 칸을 안 나눈다
(왼쪽 여백 + 번호 띄우기로 바꿨다 — 칸이 없으면 밀려날 자리도 없다).

**화면이 깨졌다는 말을 들으면 요소만 재지 말고 글자 뭉치를 잰다.** 요소만 재는 검사는
초록이어도 「안 봤다」는 뜻일 수 있다.
