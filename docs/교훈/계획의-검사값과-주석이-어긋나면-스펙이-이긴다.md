## 믿었던 것
계획서의 검사 코드는 정확하다(TDD 의 근거).

## 해본 것
④ Task 1 자동 배정 — 계획의 검사는 `{시:12,분:5}` 를, 주석은 「분은 0,3,6,…」 을 요구했다. 작업자는 검사를 따라 1분 걸음으로 짰다.

## 나온 것
Task 3 검사가 「분 % 3 === 0」을 요구해 뒤에서 깨질 것이었다. 컨트롤러가 스펙(3분 규칙)과 뒤 과제를 근거로 오타로 판정하고 검사값을 12:06 으로 고치게 했다. 하루 동안 같은 꼴의 계획 결함이 넷 더 있었다(403/401 · `나.틀림`/`나.어긋남` · `진행` 옵션 누락 · 문구 대조 줄 번호).

## 지금 결론
작업자가 「검사와 주석이 다르다」고 올리면 **막지 말고 판정**한다 — 스펙 > 계획, 뒤 과제가 무엇을 소비하는지 본다. 판정은 `Ruling:` 으로 장부에 남긴다. 하청 방식(작업자→검토→고침)이 하루 동안 Critical 3·Important 20 남짓을 잡았다 — 검토를 건너뛰지 않는다.

## 아직 모르는 것
계획을 쓸 때 검사값을 실제로 돌려 보고 넣으면 이 부류가 사라지는지.
