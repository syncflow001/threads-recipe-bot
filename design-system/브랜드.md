## 1. 이 제품이 누구를 위한 것인가

**혼자 쓰는 관제판이다.** 파는 물건이 아니고, 볼 사람은 한 명뿐이다.
그 한 명은 **비개발자**이고, 대개 「지금 잘 돌고 있나」를 확인하러 30초 들어온다.

그래서 우선순위가 보통 제품과 다르다.

| 보통 SaaS | 우리 |
|---|---|
| 처음 온 사람을 설득한다 | 이미 아는 사람이 **빨리 확인**한다 |
| 예뻐 보이는 것이 중요 | **틀린 숫자를 안 보여주는 것**이 중요 |
| 기능을 자랑한다 | 고장을 **숨기지 않는다** |

## 2. 목소리

`CLAUDE.md` §0 을 브랜드 목소리로 정식화한 것이다. 화면에 나가는 모든 글에 적용한다.

### 지킬 것

- **쉬운 사람의 말로 쓴다.** 기술 용어는 쓰기 전에 한 줄로 푼다 (「API 키 = 서비스 출입증」)
- **한국어 문장은 마침표로 끝낸다.** 콜론으로 끝내지 않는다
- **무엇을 누르면 무엇이 보이는지**까지 적는다. 「설정하세요」 가 아니라 「설정 화면 열쇠 칸에서 채우세요」
- **고장이 아닌 것은 고장이 아니라고 말한다.** 「쓸 만한 글이 없었습니다 (고장이 아닙니다)」
- **못 하는 것은 못 한다고 말한다.** 「표본 부족」 을 그럴듯한 숫자로 채우지 않는다

### 안 할 것

- 느낌표로 흥분하지 않는다. 이건 관제판이지 광고가 아니다
- 「최적화」 「최대화」 같은 자랑말을 안 쓴다
- 실패를 완곡하게 돌리지 않는다. 막혔으면 막혔다고 쓴다

### 어미 — 2026-08-25 에 정했다

사용자가 「AI 말투가 지배적이다. 실제 사람이 쓰는 언어로」라고 했다. 그래서 갈랐다.

| 무엇 | 어미 | 왜 |
|---|---|---|
| 설명 · 안내 · 빈 상태 | **`~해요` · `~예요`** | 혼자 보는 화면이다. `~합니다` 만 늘어놓으면 안내문처럼 읽힌다 |
| 실패 · 경고 · 막힘 | **`~습니다`** | 무게가 있어야 한다. 여기서 `~해요` 를 쓰면 사고가 가벼워 보인다 |

**낫표 「」 를 남발하지 않는다.** 화면 안의 다른 칸 이름을 가리킬 때만 쓴다.
강조는 굵게로 한다 — 낫표가 한 문단에 셋 넘게 들어가면 사람 글이 아니다.

**설명은 두 문장을 넘기지 않는다.** 더 길어지면 「어떻게 돌아가나요」 칸으로 뺀다.

### 낱말 — 우리가 만든 순우리말을 화면에 쓰지 않는다

사용자가 두 번 짚었다. 「AI 말투」의 정체는 어미가 아니라 **우리가 지어낸 낱말**이었다.
코드 안의 변수·클래스 이름은 그대로 둬도 된다. **화면에 뜨는 글에서만** 아래 표를 지킨다.

| 쓰지 말 것 | 쓸 것 |
|---|---|
| 견주다 · 견줍니다 · 견줄 | **비교하다 · 비교합니다 · 비교할** |
| 판 (한 판 · 판이 쌓이면) | **번 · 회 · 횟수** |
| 재다 · 잽니다 · 쟀다 · 찍다 | **측정하다 · 기록하다** |
| 쟁여 두다 | **모아 두다 · 저장하다** |
| 걷다 · 걷어 오다 | **가져오다** |
| 두드리다 (검색어를) | **검색하다** |
| 문턱 | **기준** |
| 결 (지금 결이 먹힌다) | **스타일 · 분위기** |
| 표본 | **데이터** |
| 성적 | **성과** |
| 다 자란 글 | **올린 지 하루 넘은 글** |
| 이레 · 두 이레 | **일주일 · 2주** |
| 옛 · 옛것 | **예전** |
| 믿음 (표시로 쓸 때) | **신뢰도** |
| 기둥 (지수의 구성 요소) | **항목** |
| 「~하나」 (얼마나 퍼지나) | **「~하는지」** (얼마나 퍼지는지) |

**판단 기준.** 이 낱말을 옆 사람에게 소리 내 말했을 때 되묻지 않으면 쓴다.
「견줄 날이 없어요」는 되묻는다. 「비교할 날이 없어요」는 안 되묻는다.

### 말투 표본

| 상황 | 이렇게 | 이렇게 말고 |
|---|---|---|
| 발행 멈춤 | 멈춰 있습니다 — 전체 멈춤입니다 | 시스템이 일시 정지 상태입니다 |
| 관문이 막음 | 원글에 없던 분량이 생겼습니다 | 콘텐츠 검증에 실패했습니다 |
| 표본 부족 | 도달 (표본 부족) | 도달 0% |
| 한도 초과 | 클로드 사용 한도에 걸렸습니다 | 요청 처리 중 오류 발생 |
| 빈 상태 | 아직 돌린 게 없어요 | 실행 이력이 존재하지 않습니다 |
| 안내 | 정해 둔 시각마다 한 편씩 올라가요 | 예정된 시각마다 한 편씩 발행됩니다 |

## 3. 색

**참고로 삼은 것 — TeamHub 대시보드 한 벌** (2026-08-25 에 사용자가 다시 줬다).
민트 초록 결 · 크게 둥근 흰 카드 · 그림자 거의 없음 · 옆바 전체 높이 · 맨 위 고리 통계 카드 넷.

### 뜻이 있는 색 (건드리지 말 것)

이 넷은 **꾸밈이 아니라 뜻**이다. 사용자가 이미 외운 신호라 바꾸면 오독을 부른다.

| 이름 | 값 | 뜻 |
|---|---|---|
| `--좋음` | `#15803d` | 올림 · 켜짐 · 정상 |
| `--나쁨` | `#b91c1c` | 실패 · 막힘 |
| `--회색` | `#8a7f6e` | 건너뜀 · 아직 · 확인 못 함 |
| `--강조` | `#c2410c` | 사람이 봐야 할 것 (경고 띠, 수익 막대) |

**「확인 못 함」과 「실패」는 반드시 다른 색이어야 한다.** 진단기가 셋을 가르는 이유와 같다 —
갓 만든 계정이 전부 빨갛게 뜨면 아무도 안 본다.

### 꾸밈용 초록 — 뜻이 있는 색과 헷갈리지 말 것

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| `--칠` | `#2f9e74` | 으뜸 단추 · 고른 쪽 단추 · 고리 · 초점 테두리 |
| `--칠짙` | `#25805e` | 그 위에 마우스를 올렸을 때 |
| `--칠연` | `#e4f3ec` | 꼬리표 · 낱말 주머니 · 고리 바닥 |
| `--칠연2` | `#f2f9f6` | 숫자 카드 바탕 |

⚠️ **`--칠` 은 꾸밈이고 `--좋음` 은 뜻이다.** 상태를 나타내는 곳(발행 격자의 점, 진단 ✓)에는
반드시 `--좋음` 을 쓴다. 둘이 섞이면 「초록이니 정상이겠지」라는 오독이 생긴다.

### 바탕과 글 (2026-08-25 에 옮겼다)

| 이름 | 값 | 왜 |
|---|---|---|
| `--바탕` | `#eef3f0` | 참고 대시보드의 옅은 민트빛 |
| `--판` | `#fff` | 그대로 |
| `--글` | `#1f2a37` | 따뜻한 검정 → 중립 검정 |
| `--옅은글` | `#6b7a76` | 위와 같은 이유 |
| `--선` | `#e6ece9` · `--칸선` `#dde6e2` | 위와 같은 이유 |

**뜻이 있는 넷은 손대지 않았다.**

## 4. 글꼴

본문은 시스템 기본 글꼴이고, 숫자만 고정폭이다. 이미 그렇게 돼 있다.

| 쓰임 | 글꼴 |
|---|---|
| 본문·단추·설명 | 시스템 기본 (`-apple-system`, `Pretendard` 있으면 그것) |
| **숫자·시각·아이디·로그** | 고정폭 유지 (`ui-monospace`) |

숫자를 고정폭으로 두는 이유가 있다. 발행 격자와 시각 목록이 **자리를 맞춰야 읽힌다.**

## 5. 모양 규칙

- 모서리 — 카드 `16px`(`--칸굴림`) · 단추·입력칸 `10px` · 알약꼴 배지 `999px`
- 그림자 — `0 1px 2px rgba(24,54,44,.04)` 한 겹만. 참고 대시보드는 그림자를 거의 안 쓴다
- 사이 간격 — 관제판이라 촘촘하게. `8 · 12 · 16 · 24px`
- 움직임 — `150~250ms` 만. 알림이 뜨고 지는 것 외에는 움직이지 않는다
- **이모지를 아이콘으로 쓰지 않는다.** 옆바 아이콘은 SVG 다. `ON`/`OFF` 글자는 그대로 둔다

### 자손 선택자에 `display:block` 을 걸지 마라

**두 번 당했다.** `.으뜸 span` 이 아이콘 배지까지 블록으로 만들어 아이콘이 상자 밖으로 나갔고,
`.으뜸 .글 b` 와 `.할것 b` 가 **문장 속에 쓴 `<b>` 까지** 큰 글씨 블록으로 만들어
낱말 하나가 혼자 한 줄을 먹었다.

→ 큰 글씨나 블록을 지정할 때는 **직계(`>`)로 잡는다.** `.으뜸 .글 > b` 처럼.
→ 안 그러면 그 안에 `<b>` 를 쓰는 순간 조용히 깨진다. 오류도 안 난다.

## 6. 배치 규칙 (2026-08-25, TeamHub 참고)

- **옆바는 화면 맨 위부터 바닥까지** 이어진다. 제품 이름이 옆바 맨 위에 있다
- **헤더는 쪽칸 안**에 있다. 왼쪽에 지금 보는 쪽 이름, 오른쪽에 계정 고르개
- **맨 위에 으뜸 숫자 넷** — 고리로 채움 정도를 함께 보인다. 숫자만으로는 좋은지 나쁜지 못 읽는다
- **한 카드는 한 가지만 말한다.** 「발행 현황」과 「발행 시각」을 갈라 놓은 것이 그 예다
- **접었다 폈다 하지 않는다.** 2026-08-25 에 여섯 칸을 전부 고정으로 바꿨다 (사용자가 정했다)
- 카드 머리는 왼쪽 제목 · 오른쪽 조작 하나 (`.칸머리`)
- 바닥에 한 줄 — 마지막으로 받아온 때
